# 第 10 节学习资料：BuildAdmin 路由与动态页面

## 1. 学习目标

这份教材会把第 09 节的静态路由推进到“菜单数据决定可访问页面”。学完后，你应当能够：

- 分清动态参数、动态导入和动态注册路由；
- 理解为什么后台系统常把菜单和权限规则放在服务端；
- 看懂 Vite 的 `import.meta.glob()` 返回什么；
- 把组件路径字符串安全地转换成 Vue 组件加载函数；
- 用 `router.addRoute()` 在运行时挂载业务页面；
- 看懂 BuildAdmin 后台动态路由的关键调用链；
- 实现一个不依赖真实后端和 Pinia 的缩小版动态路由系统。

## 2. 前置知识

### 2.1 第 09 节已经掌握的静态路由

当前练习项目把路由写在 `src/router/index.ts` 中：

```ts
{
  path: '/admin',
  component: () => import('@/layouts/AdminLayout.vue'),
  children: [
    { path: 'home', component: () => import('@/views/home/HomeView.vue') },
  ],
}
```

应用一启动，这些记录就被传给 `createRouter()`。无论当前登录者有什么权限，前端都已经知道 `home` 页面路由存在。这叫静态路由。

### 2.2 动态参数不等于动态路由注册

下面的 `:id` 会变化：

```ts
{ path: 'users/:id', component: UserDetailView }
```

但整条路由记录仍是启动时写好的，因此它只是动态参数。今天所说的动态路由，是在应用运行期间执行：

```ts
router.addRoute(...)
```

两者可以同时存在：运行时注册一条路径为 `users/:id` 的路由。

### 2.3 后台为什么需要运行时路由

假设系统有管理员、运营人员和只读审计员：

| 角色 | 可见页面 |
| --- | --- |
| 管理员 | 首页、用户、角色、系统设置 |
| 运营人员 | 首页、用户 |
| 审计员 | 首页、审计日志 |

如果全部写成静态路由，前端仍需要额外判断每个角色能否进入。大型后台通常让服务端根据账号权限返回规则，前端据此生成菜单和注册页面。

不过必须注意：前端动态路由主要改善界面和导航体验，不能代替后端鉴权。用户即使绕过前端，也不能从后端取得无权限数据；真正的安全边界仍在服务端。

## 3. 核心概念

### 3.1 从规则数据到 Vue 页面，中间缺了一步

模拟后端可能返回：

```ts
{
  path: 'home',
  name: 'admin-home',
  title: '首页',
  component: '/src/views/home/HomeView.vue'
}
```

这里的 `component` 只是字符串。Vue 不能把文件路径字符串当作组件渲染：

```ts
// 错误思路
router.addRoute({
  path: 'home',
  component: rule.component,
})
```

Router 的 `component` 需要组件对象，或返回组件模块的加载函数。前端必须建立映射：

```text
组件路径字符串 -> Vite 能加载的函数
```

### 3.2 import.meta.glob 是什么

Vite 提供：

```ts
    const viewModules = import.meta.glob('/src/views/**/*.vue')
```

可把结果理解为：

```ts
{
  '/src/views/home/HomeView.vue': () => import('真实的 HomeView 文件'),
  '/src/views/user/UserDetailView.vue': () => import('真实的 UserDetailView 文件'),
}
```

键是文件路径，值是懒加载函数。默认不会立刻下载并执行所有页面模块，访问对应页面时才加载。

这也解释了为什么路径必须完全一致：大小写、目录、文件名或斜杠不一致，查找结果都是 `undefined`。

### 3.3 为什么不能直接使用任意变量 import

你可能想到：

```ts
const component = () => import(rule.component)
```

构建工具需要在构建阶段知道可能包含哪些文件，才能把它们打进产物并进行代码分割。来自服务器的任意字符串太开放，也不安全。`import.meta.glob()` 明确限定“只允许 `src/views` 下匹配到的 Vue 文件”，同时建立构建工具可分析的映射。

因此组件映射也可以看作一份前端白名单：服务端只能选择前端构建产物中真实存在、且被 glob 覆盖的页面。

### 3.4 router.addRoute

注册顶层路由：

```ts
router.addRoute({
  path: '/about',
  name: 'about',
  component: AboutView,
})
```

注册到已有命名父路由下：

```ts
router.addRoute('admin', {
  path: 'home',
  name: 'admin-home',
  component: viewModules['/src/views/home/HomeView.vue'],
})
```

这里有两个关键点：

1. 父路由必须有 `name: 'admin'`，Router 才能准确找到挂载位置。
2. 子路由使用相对路径 `home`，最终完整路径为 `/admin/home`。

### 3.5 防止重复注册

初始化逻辑可能因页面刷新、重新登录或热更新执行多次。路由名称应唯一，并在注册前检查：

```ts
if (router.hasRoute(rule.name)) {
  return
}
```

名称不只是导航的别名，也是动态路由去重的稳定标识。

### 3.6 菜单树和路由表不是一回事

它们可以来自同一份规则，但职责不同：

| 对比项 | 菜单树 | 路由表 |
| --- | --- | --- |
| 服务对象 | 侧边栏、顶部导航 | Vue Router |
| 主要作用 | 告诉用户可以点击什么 | 匹配 URL 并渲染组件 |
| 目录节点 | 可以存在 | 通常不需要注册为页面 |
| 按钮权限 | 通常不显示为页面菜单 | 也不注册为页面路由 |
| 外链 | 可作为菜单项 | 可能直接新窗口打开，无需内部路由 |
| 页面组件 | 可保存组件路径供转换 | 必须是组件或加载函数 |

例如“权限管理”可能只是一个菜单目录，下面有“用户管理”和“角色管理”。目录负责组织视觉层级，不一定对应一个 Vue 页面。

### 3.7 动态路由的初始化时机

真实系统通常按以下顺序工作：

```text
确认登录态 -> 请求当前用户菜单 -> 注册动态路由 -> 跳转目标页
```

如果用户先导航到 `/admin/home`，而路由还没注册，通配 404 可能先匹配。真实项目会在登录恢复或守卫中协调初始化时机。

本节为了聚焦转换机制，使用本地同步规则，在 Router 导出前注册。第 11 节学习 Pinia，第 16～17 节再把它接入登录态和路由守卫。

## 4. BuildAdmin 源码拆解

### 4.1 静态后台外壳

文件：`buildadmin/web/src/router/static/adminBase.ts`

核心结构是：

```ts
const adminBaseRoute = {
  path: '/admin',
  name: 'admin',
  component: () => import('/@/layouts/backend/index.vue'),
  redirect: '/admin/loading',
  children: [loadingRoute],
}
```

后台布局和 loading 页面是静态的，因为进入后台、请求菜单之前就需要它们。用户管理、角色管理等业务页面则由后端菜单动态决定。

### 4.2 初始化接口是动态规则入口

文件：`buildadmin/web/src/layouts/backend/index.vue`

布局挂载后调用 `init()`，其中执行后台初始化接口：

```ts
index().then((res) => {
  if (res.data.menus) {
    handleAdminRoute(res.data.menus)
  }
})
```

接口还返回站点配置和管理员信息，但本节只追踪 `menus`。

### 4.3 handleAdminRoute 一次生成三种结果

文件：`buildadmin/web/src/utils/router.ts`

核心入口：

```ts
export const handleAdminRoute = (routes: any) => {
  const viewsComponent = import.meta.glob('/src/views/backend/**/*.vue')
  addRouteAll(viewsComponent, routes, adminBaseRoute.name as string)

  const navTabs = useNavTabs()
  navTabs.setTabsViewRoutes(handleMenuRule(routes, '/admin/'))
  navTabs.fillAuthNode(handleAuthNode(routes, '/admin/'))
}
```

三条输出分别是：

- `addRouteAll`：注册可访问页面；
- `handleMenuRule`：生成侧边栏和标签页使用的菜单树；
- `handleAuthNode`：收集按钮权限。

### 4.4 addRouteAll 为什么要递归

后端菜单通常是树：

```text
权限管理（目录）
├── 用户管理（页面）
└── 角色管理（页面）
```

`addRouteAll()` 遍历当前层，遇到可注册的 `tab` 或 `iframe` 页面就处理，然后继续递归 `children`。目录不会被误当成普通页面，但它下面的页面仍能被找到。

### 4.5 addRouteItem 完成最后转换

对普通内部标签页，BuildAdmin 的关键逻辑可以缩写为：

```ts
const routeBaseInfo = {
  path: route.path,
  name: route.name,
  component: viewsComponent[route.component],
  meta: {
    title: route.title,
    icon: route.icon,
    keepalive: route.keepalive,
  },
}

router.addRoute('admin', routeBaseInfo)
```

这就是整个机制的心脏：服务端字符串 `route.component` 被用作映射表的键，取得真正的组件加载函数。

### 4.6 为什么页面都挂到 admin 下

调用：

```ts
router.addRoute('admin', routeBaseInfo)
```

让动态页面成为 `/admin` 的子路由。这样它们都会渲染在后台布局的 RouterView 中，自动共享头部、侧边栏和标签页容器。

### 4.7 BuildAdmin 的 loading 中转页

访问后台时，业务路由可能尚未注册，因此静态 `/admin/loading` 先提供一个合法页面。初始化接口返回并完成动态注册后，系统再跳转到上次页面或第一个有效菜单。这是对初始化时序的实际处理。

## 5. 完整示例与运行过程

下面是适合本节练习项目的完整最小实现。建议理解后手写，并保持你现有页面样式。

### 5.1 `src/mock/adminMenu.ts`

```ts
export interface AdminMenuRule {
  path: string
  name: string
  title: string
  type: 'menu' | 'menu_dir' | 'button'
  menuType?: 'tab' | 'link'
  component?: string
  children?: AdminMenuRule[]
}

export const adminMenuRules: AdminMenuRule[] = [
  {
    path: 'home',
    name: 'admin-home',
    title: '首页',
    type: 'menu',
    menuType: 'tab',
    component: '/src/views/home/HomeView.vue',
  },
  {
    path: 'users/:id',
    name: 'user-detail',
    title: '用户详情',
    type: 'menu',
    menuType: 'tab',
    component: '/src/views/user/UserDetailView.vue',
  },
]
```

### 5.2 `src/router/dynamic.ts`

```ts
import type { RouteRecordRaw } from 'vue-router'
import type { AdminMenuRule } from '@/mock/adminMenu'
import router from './index'

const viewModules = import.meta.glob('/src/views/**/*.vue')

export function registerDynamicRoutes(rules: AdminMenuRule[]) {
  const registeredNames: string[] = []

  for (const rule of rules) {
    if (rule.type !== 'menu' || rule.menuType !== 'tab' || !rule.component) {
      continue
    }

    if (router.hasRoute(rule.name)) {
      continue
    }

    const component = viewModules[rule.component]
    if (!component) {
      console.warn(`[dynamic-route] 找不到页面组件：${rule.component}`)
      continue
    }

    const route: RouteRecordRaw = {
      path: rule.path,
      name: rule.name,
      component,
      meta: {
        title: rule.title,
      },
    }

    router.addRoute('admin', route)
    registeredNames.push(rule.name)
  }

  return registeredNames
}
```

这个版本先处理一层规则。若你主动增加目录树，可以把遍历改为递归；递归不是本节最低验收要求。

### 5.3 `src/router/index.ts`

为避免 `dynamic.ts` 和 `index.ts` 相互导入形成循环依赖，更稳妥的写法是让注册函数接收 Router 实例。推荐将上节示例改为：

```ts
// dynamic.ts
import type { Router, RouteRecordRaw } from 'vue-router'
import type { AdminMenuRule } from '@/mock/adminMenu'

const viewModules = import.meta.glob('/src/views/**/*.vue')

export function registerDynamicRoutes(router: Router, rules: AdminMenuRule[]) {
  // 循环与注册逻辑同上
}
```

然后在路由入口中：

```ts
import { createRouter, createWebHistory } from 'vue-router'
import { adminMenuRules } from '@/mock/adminMenu'
import { registerDynamicRoutes } from './dynamic'

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    { path: '/', redirect: '/login' },
    {
      path: '/login',
      name: 'login',
      component: () => import('@/views/login/LoginView.vue'),
    },
    {
      path: '/admin',
      name: 'admin',
      component: () => import('@/layouts/AdminLayout.vue'),
      redirect: '/admin/home',
    },
    {
      path: '/:pathMatch(.*)*',
      name: 'not-found',
      component: () => import('@/views/error/NotFoundView.vue'),
    },
  ],
})

registerDynamicRoutes(router, adminMenuRules)

export default router
```

这里在导出前同步注册本地规则，所以初次匹配 `/admin/home` 时路由已经存在。真实接口是异步的，需要 loading 页或守卫协调。

### 5.4 `src/layouts/AdminLayout.vue` 菜单片段

```vue
<script setup lang="ts">
import { computed } from 'vue'
import { adminMenuRules } from '@/mock/adminMenu'

const visibleMenus = computed(() =>
  adminMenuRules.filter(
    (rule) => rule.type === 'menu' && rule.menuType === 'tab',
  ),
)
</script>

<template>
  <aside>
    <RouterLink
      v-for="menu in visibleMenus"
      :key="menu.name"
      :to="`/admin/${menu.path.replace('/:id', '/8')}`"
    >
      {{ menu.title }}
    </RouterLink>
  </aside>
  <main>
    <RouterView />
  </main>
</template>
```

`users/:id` 是路由模式，真实菜单通常会链接到用户列表而不是某个详情页。本节为了复用第 09 节页面，将 `:id` 替换成演示值 `8`。后续 CRUD 课程会改成列表进入详情或编辑。

### 5.5 运行时究竟发生了什么

1. 浏览器加载应用，执行 `src/router/index.ts`。
2. `createRouter()` 先创建登录、后台布局和 404 等静态路由。
3. `registerDynamicRoutes()` 收到模拟菜单规则。
4. 它从 `viewModules` 中按组件路径找到懒加载函数。
5. `router.addRoute('admin', ...)` 把 `home` 和 `users/:id` 挂到后台布局下。
6. 访问 `/admin/home` 时，顶层 RouterView 显示 `AdminLayout`。
7. `AdminLayout` 内的 RouterView 显示动态注册的 `HomeView`。
8. 侧边栏也读取同一份规则，所以导航显示与可访问页面保持一致。

## 6. 常见错误

### 错误一：把字符串当组件

```ts
component: rule.component
```

规则中的路径只是查找键，必须先执行：

```ts
const component = viewModules[rule.component]
```

### 错误二：glob 范围与规则路径不一致

```ts
import.meta.glob('/src/views/admin/**/*.vue')
```

但页面实际在 `/src/views/home/HomeView.vue`，映射中自然找不到。glob 范围和规则路径必须覆盖真实文件。

### 错误三：父路由没有名称

```ts
router.addRoute('admin', route)
```

要求父路由存在 `name: 'admin'`。仅有 `path: '/admin'` 不够。

### 错误四：动态子路由写完整路径造成理解混乱

挂到 `admin` 下时，推荐写：

```ts
path: 'home'
```

它会组合为 `/admin/home`。绝对路径虽有特定用途，但本节应保持父子 URL 关系清楚。

### 错误五：先进入 404，之后才注册路由

异步请求菜单时，当前导航可能已经匹配了兜底路由。应在守卫中等待初始化，或先进入静态 loading 页面，注册完成后再跳转。BuildAdmin 使用后台 loading 子路由处理这个阶段。

### 错误六：重复添加相同名称

初始化多次时，先检查：

```ts
router.hasRoute(rule.name)
```

### 错误七：把动态路由当成安全措施

不显示菜单、未注册页面，都不能阻止攻击者直接请求 API。后端仍必须验证 token、角色和具体操作权限。

### 错误八：菜单与路由强行一对一

目录、按钮、外链不一定是内部页面路由；某些隐藏详情页可能需要路由却不显示在菜单。转换时应根据 `type` 和 `menuType` 分流。

## 8. 参考答案

1. 动态参数是已存在路由中可变化的 URL 片段；动态注册是在应用运行后才通过 `addRoute()` 加入整条路由记录。
2. 键是匹配到的组件文件路径，值默认是对应模块的懒加载函数。
3. Vue Router 需要组件对象或组件加载函数；字符串只是服务端数据，必须用它从本地组件映射中取得真正的加载函数。
4. 它是父路由的名称，表示把新路由注册为名为 `admin` 的路由的子路由。
5. 子路由的相对路径会与父路径组合，能明确表达它属于后台布局，最终结果仍是 `/admin/home`。
6. 它用于判断某个命名路由是否已存在，避免初始化重复执行时再次注册。
7. 目录只负责组织菜单层级，没有独立页面组件，也不需要匹配 URL 渲染页面。
8. 前端代码和请求都可能被绕过；API 必须由后端再次验证用户是否有权读取数据或执行操作。
9. 动态页面路由、侧边栏/标签页菜单树、按钮权限节点。
10. URL 可能先被 404 捕获。BuildAdmin 先提供静态的后台 loading 子路由，获取菜单并注册完成后再跳到目标页或第一个菜单。
