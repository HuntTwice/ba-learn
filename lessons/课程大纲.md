# BuildAdmin 前端 30 天课程大纲

## 一、课程信息

| 项目 | 内容 |
| --- | --- |
| 学习周期 | 30 天，每天 1 节，共 30 节 |
| 建议投入 | 每天 2～3 小时：学习 40 分钟、读源码 40 分钟、动手 60～100 分钟、复盘 10 分钟 |
| 学习对象 | 有少量 HTML、CSS、JavaScript 基础的前端初学者 |
| 源码目录 | `F:\project\MyProject\buildadmin\web` |
| 练习目录 | `F:\project\MyProject\ba-learn` |
| 最终成果 | 独立复刻一个具备登录、布局、权限路由、CRUD、主题切换和数据看板的后台管理系统 |
| 技术主线 | Vue 3、TypeScript、Vite、Vue Router、Pinia、Axios、Element Plus、ECharts |

## 二、30 天结课标准

完成课程后，学生应当能够：

1. 用自己的话说明 BuildAdmin 前端从启动、登录到呈现后台页面的完整流程。
2. 看懂 Vue 单文件组件、Composition API 和常用 TypeScript 类型。
3. 独立搭建后台布局、路由、状态管理、请求层和登录鉴权。
4. 独立完成一个列表查询、新增、编辑、删除、分页和表单校验的 CRUD 模块。
5. 理解 BuildAdmin 的动态菜单、标签页、权限控制和通用表格设计，而不是机械复制源码。
6. 完成一个可运行、可构建、结构清晰的复刻项目，并能讲清关键设计取舍。

## 三、课程阶段

| 阶段 | 天数 | 阶段目标 | 阶段作品 |
| --- | --- | --- | --- |
| 第一阶段：建立地图 | 第 1～3 天 | 会运行、会定位、看懂项目入口与模块关系 | 能运行项目并追踪启动链路 |
| 第二阶段：Vue 与 TS 地基 | 第 4～8 天 | 掌握读写 BuildAdmin 页面必需的 Vue 3、TS、样式基础 | 登录页静态原型和可复用组件 |
| 第三阶段：后台骨架 | 第 9～14 天 | 完成路由、状态、布局、菜单、标签页和主题 | 可导航的后台壳子 |
| 第四阶段：数据与登录 | 第 15～18 天 | 完成请求封装、登录态、守卫和错误处理 | 可模拟登录的后台系统 |
| 第五阶段：CRUD 核心 | 第 19～24 天 | 理解并复刻表格、搜索、表单和权限按钮 | 完整的用户管理模块 |
| 第六阶段：产品化与结课 | 第 25～30 天 | 完成看板、配置、质量检查、综合复刻与答辩 | 可演示的后台管理系统 |

## 四、每日课程安排

| 节次 | 课程名 | 核心知识 | 当日实践产物 | 验收重点 |
| --- | --- | --- | --- | --- |
| 第 01 节 | 认识 BuildAdmin 与制定复刻目标 | 前后端边界、技术栈、学习方法、成品范围 | 明确复刻范围 | 能区分“源码项目”和“练习项目”，并讲清准备复刻的核心功能 |
| 第 02 节 | 跑通项目与认识开发工具链 | Node、包管理器、Vite、开发与构建命令 | 可运行的项目 | 能讲清浏览器、Vite 与 Vue 源码如何配合，并正确使用开发和构建命令 |
| 第 03 节 | 阅读前端目录与启动链路 | `main.ts`、`App.vue`、插件注册、目录职责 | 源码追踪结果 | 能从入口追踪到首个页面，并说明关键目录的职责 |
| 第 04 节 | TypeScript 阅读生存指南 | 基础类型、接口、联合类型、泛型、类型导入 | 类型练习代码 | 能读懂并正确使用项目中常见的 TypeScript 类型 |
| 第 05 节 | Vue 单文件组件与响应式 | SFC、`ref`、`reactive`、模板绑定、事件 | 计数与用户卡片组件 | 能解释状态变化如何触发视图更新 |
| 第 06 节 | 计算属性侦听器与生命周期 | `computed`、`watch`、`onMounted`、副作用 | 可筛选用户列表 | 正确选择 computed 或 watch，并说明理由 |
| 第 07 节 | 组件通信与插槽 | props、emits、`v-model`、slot、组件边界 | 通用弹窗和搜索栏组件 | 父子组件数据流清晰，不直接篡改 props |
| 第 08 节 | 后台页面样式与 Element Plus | CSS 布局、SCSS、组件库使用、响应式界面 | 静态登录页 | 布局接近目标，能说明原生元素与组件库组件的分工 |
| 第 09 节 | Vue Router 基础 | 路由表、嵌套路由、参数、导航 | 登录、首页、用户页路由 | 三个页面可导航，刷新后路由仍正确 |
| 第 10 节 | BuildAdmin 路由与动态页面 | 静态路由、动态导入、后端菜单转路由 | 可运行的简化动态路由 | 能实现菜单规则到页面路由的转换，并讲清关键步骤 |
| 第 11 节 | Pinia 状态管理 | store、state、getters、actions、持久化概念 | 用户与应用配置 store | 能说明局部状态和全局状态的区别 |
| 第 12 节 | 后台整体布局 | Layout、Header、Aside、Main、RouterView | 后台基础框架 | 页面包含头部、侧栏、内容区，尺寸关系合理 |
| 第 13 节 | 递归菜单与菜单状态 | 树结构、递归组件、展开项、当前路由 | 多级侧边菜单 | 支持至少三级菜单并高亮当前页面 |
| 第 14 节 | 标签页导航与页面缓存 | navTabs、路由元信息、KeepAlive、关闭策略 | 多标签导航 | 可新增、切换、关闭标签，固定首页不可误删 |
| 第 15 节 | Axios 请求层 | 实例、基础地址、拦截器、泛型响应、取消请求概念 | 请求客户端与模拟 API | 页面不直接散写请求配置，错误可统一处理 |
| 第 16 节 | 登录页与登录状态 | 表单模型、校验、token、用户信息 | 可模拟成功和失败的登录页 | 登录成功跳转，失败提示明确，密码字段有校验 |
| 第 17 节 | 路由守卫与权限入口 | 前置守卫、白名单、重定向、登录恢复 | 登录访问控制 | 未登录不能进入后台，登录后能回到原目标页 |
| 第 18 节 | 请求错误与用户反馈 | 业务错误、HTTP 错误、超时、Loading、防重复提交 | 全局反馈机制 | 至少演示成功、业务失败、网络失败三种状态 |
| 第 19 节 | 读懂 BuildAdmin CRUD 架构 | API、页面、表格控制器、状态流转 | CRUD 源码追踪结果 | 能指出列表、表单、API 和控制状态各自职责 |
| 第 20 节 | 用户列表与分页 | 表格列、数据获取、分页、加载状态、空状态 | 用户列表页 | 分页和加载状态可用，列配置清晰 |
| 第 21 节 | 搜索排序与重置 | 查询模型、条件组合、排序、防抖、重置 | 用户搜索区 | 搜索条件与请求参数一致，可一键恢复默认状态 |
| 第 22 节 | 新增编辑表单 | 弹窗、表单复用、默认值、校验、提交 | 新增/编辑用户弹窗 | 同一表单支持新增和编辑，提交后列表正确更新 |
| 第 23 节 | 删除批量操作与安全交互 | 单删、批删、选择状态、二次确认、异常恢复 | 完整删除流程 | 未选择时不可批删，删除前确认，失败不丢失页面状态 |
| 第 24 节 | 通用表格与字段渲染思想 | 配置驱动、插槽、自定义渲染、组件抽象边界 | 两个模块复用的表格组件 | 至少两种业务列表复用，且保留自定义列能力 |
| 第 25 节 | 按钮级权限与角色菜单 | RBAC、权限标识、指令或组件封装、无权处理 | 角色切换与权限按钮 | 两种角色看到不同菜单和操作按钮 |
| 第 26 节 | 国际化主题与全屏 | vue-i18n、暗色模式、CSS 变量、配置持久化 | 中英文和明暗主题切换 | 刷新后偏好保留，核心页面两种主题可读 |
| 第 27 节 | 数据看板与 ECharts | 指标卡、图表 option、响应式 resize、数据空态 | 首页数据看板 | 至少 3 个指标和 2 张图，窗口变化不溢出 |
| 第 28 节 | 工程质量与构建检查 | ESLint、格式化、类型检查、生产构建、环境变量 | 质量检查记录 | 类型检查和生产构建通过，列出并修复主要问题 |
| 第 29 节 | 综合复刻冲刺 | 模块整合、交互一致性、缺陷修复、README | 可演示的完整复刻项目 | 登录、权限、布局、CRUD、主题、看板形成闭环 |
| 第 30 节 | 结课验收与源码对照复盘 | 架构讲解、差异分析、重构方向、后续路线 | 完整项目演示与复盘 | 能独立演示、讲清核心流程，并说明自己的实现与源码的关键差异 |

## 五、复刻项目的最小功能范围

结课作品暂定为“轻量用户运营后台”，必须包含：

1. 登录与退出。
2. 后台基础布局、折叠菜单、面包屑或标签页。
3. 首页指标卡与图表。
4. 用户管理 CRUD、搜索、分页和批量删除。
5. 角色切换、动态菜单和按钮级权限。
6. 明暗主题切换，设置能够持久化。
7. 统一请求封装、Loading、成功提示和错误提示。
8. TypeScript 类型检查与生产构建通过。

不把真实后端开发列为本期硬性目标。前期使用本地模拟数据，把精力集中在前端架构；如已有可用接口，可在第 29 节替换模拟 API。

## 六、统一课程文件规范

以后每节课创建 `lessons/第xx节-课程名/`，其中至少包含：

- `第xx节-课程名.md`：互动课程记录。
- `第xx节-学习资料.md`：独立、完整、可复习的教材；练习课可省略。

每份互动课程记录固定使用以下章节：

1. 课程信息
2. 本节目标
3. 开课诊断
4. 学习路线
5. Coach 引导与学生回答
6. 动手任务（明确目录和文件名）
7. 本节输出
8. 验收标准
9. 学习小结
10. 进度更新

每份学习资料固定使用以下章节：

1. 学习目标
2. 前置知识
3. 核心概念
4. BuildAdmin 源码拆解
5. 完整示例与运行过程
6. 常见错误
7. 自测题
8. 参考答案

## 七、课程推进规则

1. 每次只开展当天一节课，不提前灌输后续全部内容。
2. 开课时先检查上一节产物，再根据掌握程度调整讲解和练习量。
3. 涉及编码时，Coach 必须给出练习项目中的明确目录与文件名。
4. 学生完成编码后通知 Coach；Coach 先反馈关键知识点，再处理代码风格细节。
5. 每节课结束后更新 `学习进度.md`，记录状态、产物、掌握情况和下一步。
6. 如果某节未通过验收，优先补齐核心目标；30 天编号不变，必要时缩减拓展项。
7. 课程验收只看知识理解、实际代码、运行结果和解决问题的过程，不要求学生用固定字数、表格、Mermaid、报告或其他指定形式提交答案。
8. 图表和结构化内容可以由 Coach 作为教材或讲解工具提供，但不得作为学生必须完成的输出形式；学生可用自己最自然的方式回答。
9. 学生主要完成能促进理解的关键代码；类型检查、生产构建、重复调用、异常路径和其他机械性验证默认由 Coach 执行并反馈，不把重复测试步骤转交给学生。
