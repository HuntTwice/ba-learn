# 第 13 节学习资料：递归菜单与菜单状态

## 1. 学习目标

学完本资料后，你应能把后台菜单设计成树形数据，用 Vue 递归组件渲染任意层级，处理目录展开、当前路由高亮和刷新恢复，并读懂 BuildAdmin 垂直菜单的核心实现。

## 2. 前置知识

### 2.1 什么是树结构

树由节点组成。一个节点可以有子节点；没有子节点的节点叫叶子。后台菜单通常天然是一棵树：

```text
后台菜单
├── 首页（叶子）
└── 系统管理（分支）
    └── 用户管理（分支）
        └── 用户详情（叶子）
```

对应 TypeScript 类型可以引用自己：

```ts
interface MenuNode {
  name: string
  title: string
  path?: string
  children?: MenuNode[]
}
```

`children?: MenuNode[]` 表示每个节点的孩子仍是同一种节点。数据能表达两层、三层或更多层，而不必分别定义 `child`、`grandchild`。

### 2.2 目录和页面菜单

目录负责组织子菜单，通常只展开或收起；页面菜单负责导航。两者不要混为一谈：

```ts
const menus: MenuNode[] = [
  {
    name: 'system',
    title: '系统管理',
    children: [
      {
        name: 'user-management',
        title: '用户管理',
        children: [
          {
            name: 'user-detail',
            title: '用户详情',
            path: 'users/:id',
          },
        ],
      },
    ],
  },
]
```

如果目录也随意携带页面路径，点击动作会变得含糊：到底是展开，还是跳转？成熟系统可以设计“可跳转目录”，但初学阶段应保持单一职责。

### 2.3 递归的三要素

递归函数或递归组件需要：

1. 相同问题：每一层都是“渲染一组菜单节点”。
2. 缩小问题：下一次只处理当前节点的 `children`。
3. 终止条件：节点没有可见子节点时渲染叶子，不再调用自己。

递归不是无限循环。只要数据是有限的树，并且每次进入更小的子数组，就会到达叶子。

### 2.4 Vue 组件为什么能递归

单文件组件可以在模板中按自身组件名调用自己。假设文件名为 `AdminMenuTree.vue`：

```vue
<AdminMenuTree v-if="node.children?.length" :menus="node.children" />
```

每个组件实例只负责一层。父实例渲染第一层，子实例渲染第二层，孙实例渲染第三层。它们共享一份组件定义，但接收不同的 `menus`。

## 3. 核心概念

### 3.1 分支渲染与叶子渲染

递归菜单的核心不是循环本身，而是对每个节点做一次判断：

```text
节点有可见 children？
├── 是：渲染目录，再递归渲染 children
└── 否：渲染叶子菜单项
```

按钮权限节点不应该成为侧栏菜单。应先得到可见子节点，再判断当前节点是不是分支；否则一个只有按钮 children 的页面可能被错误渲染成空目录。

### 3.2 稳定且唯一的节点标识

Vue 的 `key`、Element Plus 菜单的 `index`、展开集合都需要标识。好的标识必须：

- 在整棵树中唯一。
- 刷新前后稳定。
- 不依赖数组下标。
- 不因标题翻译或修改而改变。

业务约束能保证路由 `name` 全局唯一时，可以使用 `name`。如果不同目录可能重复 name，则应使用从祖先到当前节点拼成的完整键，例如 `system/user/detail`。数组下标不适合，因为插入或排序菜单后它会变化。

### 3.3 三类菜单状态

菜单常见三类状态：

| 状态 | 典型来源 | 原因 |
| --- | --- | --- |
| 当前激活项 | 当前路由 | 地址才是当前页面的事实来源 |
| 展开的目录 | 用户交互 + 当前路由祖先链 | 用户可自由浏览，但当前项必须可见 |
| 整体是否折叠 | 应用配置 store | Header、Aside 等多个组件可能共同使用 |

高亮若只在点击时写入 `ref`，刷新、地址栏导航和浏览器前进后退就可能失真。应使用 `useRoute()` 和 `computed()` 从当前路由推导。

### 3.4 动态参数路径的匹配

菜单规则可能是 `users/:id`，真实地址却是 `/admin/users/8`，二者不能直接按字符串相等比较。更稳妥的方式是让已注册路由的 `name` 成为关联标识：

```ts
const route = useRoute()
const activeMenu = computed(() => String(route.name ?? ''))
```

只要动态路由注册时使用菜单节点的 `name`，访问任意用户 ID 时 `route.name` 都仍是 `user-detail`。这比手动替换参数可靠。

### 3.5 如何找到当前节点的祖先

为了自动展开当前页面的父目录，可以深度优先搜索树：

```ts
function findAncestorNames(
  nodes: MenuNode[],
  targetName: string,
  ancestors: string[] = [],
): string[] | undefined {
  for (const node of nodes) {
    if (node.name === targetName) return ancestors

    const result = findAncestorNames(
      node.children ?? [],
      targetName,
      [...ancestors, node.name],
    )

    if (result) return result
  }
}
```

运行过程：寻找 `user-detail` 时，先检查 `system`，再带着 `['system']` 进入其 children；进入 `user-management` 时，祖先变为 `['system', 'user-management']`；找到目标后返回这条祖先链。

注意：生产代码应先过滤按钮等非菜单节点，避免把不可见节点加入展开集合。

### 3.6 递归注册动态路由

菜单数据从扁平数组变成树后，原来只遍历第一层的路由注册逻辑会漏掉深层页面。可以把“访问一个节点”也写成递归：

```ts
function visitRules(rules: AdminMenuRule[]) {
  for (const rule of rules) {
    if (rule.children?.length) visitRules(rule.children)

    if (rule.type !== 'menu' || rule.menuType !== 'tab' || !rule.component) {
      continue
    }

    // 查找组件并注册叶子路由
  }
}
```

菜单渲染和路由注册都读取同一棵业务树，但职责不同：菜单渲染决定界面结构；路由注册决定哪些 URL 可以加载哪些页面。

## 4. BuildAdmin 源码拆解

### 4.1 `menuVertical.vue`：状态容器

BuildAdmin 的垂直菜单最外层使用 `el-menu`，传入：

- `default-active`：当前激活菜单的 key。
- `collapse`：侧栏是否折叠。
- `unique-opened`：是否只允许一个同级目录展开。
- `collapse-transition`：是否启用折叠动画。

随后把路由菜单数组交给 `MenuTree`。这体现了清楚的职责：外层容器管理整体状态，树组件只负责递归结构。

### 4.2 `menuTree.vue`：递归结构

其逻辑可以简化为：

```vue
<template v-for="menu in menus" :key="getMenuKey(menu)">
  <el-sub-menu v-if="menu.children?.length" :index="getMenuKey(menu)">
    <template #title>{{ menu.meta?.title }}</template>
    <MenuTree :menus="menu.children" />
  </el-sub-menu>

  <el-menu-item v-else :index="getMenuKey(menu)">
    {{ menu.meta?.title }}
  </el-menu-item>
</template>
```

真实源码还处理图标、国际化、横向菜单点击、默认图标和主题颜色。递归的本质仍只有“有孩子渲染分支，否则渲染叶子”。

### 4.3 当前路由如何激活菜单

BuildAdmin 不把“最后点击的 DOM”当作页面事实，而是在挂载和路由更新时，根据当前 route 找到标签页数据，再由 `getMenuKey()` 得到激活标识。这样程序化跳转和浏览器导航也能同步菜单。

练习项目规模较小，可以直接使用 `computed(() => route.name)`；核心原则相同：激活项来自当前路由。

### 4.4 为什么练习不复制全部源码

BuildAdmin 同时支持多种布局、外链、iframe、国际化和权限菜单。今天只抽取三个骨架：

1. 外层菜单容器持有状态。
2. `MenuTree` 递归渲染结构。
3. 当前路由决定激活项。

先掌握骨架，再理解产品扩展，源码才不会变成一团需要死记的细节。

## 5. 完整示例与运行过程

以下是独立可理解的参考实现。课堂实践会根据现有代码逐步完成，不建议一开始整段复制。

### 5.1 树形菜单数据：`src/mock/adminMenu.ts`

```ts
export interface AdminMenuRule {
  path?: string
  name: string
  title: string
  type: 'menu' | 'menu_dir' | 'button'
  menuType?: 'tab' | 'link'
  component?: string
  children?: AdminMenuRule[]
}

export const adminMenuRules: AdminMenuRule[] = [
  {
    name: 'admin-home',
    title: '首页',
    type: 'menu',
    menuType: 'tab',
    path: 'home',
    component: '/src/views/home/HomeView.vue',
  },
  {
    name: 'system',
    title: '系统管理',
    type: 'menu_dir',
    children: [
      {
        name: 'user-management',
        title: '用户管理',
        type: 'menu_dir',
        children: [
          {
            name: 'user-detail',
            title: '用户详情',
            type: 'menu',
            menuType: 'tab',
            path: 'users/:id',
            component: '/src/views/user/UserDetailView.vue',
          },
        ],
      },
    ],
  },
]
```

目录不需要 `path` 和 `component`，所以这里把 `path` 改成可选属性。所有叶子路径仍相对于父路由 `/admin`。

### 5.2 递归树：`src/layouts/components/AdminMenuTree.vue`

```vue
<template>
  <template v-for="item in visibleMenus" :key="item.name">
    <el-sub-menu v-if="visibleChildren(item).length" :index="item.name">
      <template #title>{{ item.title }}</template>
      <AdminMenuTree :menus="visibleChildren(item)" />
    </el-sub-menu>

    <el-menu-item v-else-if="item.type === 'menu'" :index="item.name" @click="openMenu(item)">
      {{ item.title }}
    </el-menu-item>
  </template>
</template>

<script setup lang="ts">
import { computed } from 'vue'
import { useRouter } from 'vue-router'
import type { AdminMenuRule } from '@/mock/adminMenu'

defineOptions({ name: 'AdminMenuTree' })

const props = defineProps<{ menus: AdminMenuRule[] }>()
const router = useRouter()

const visibleMenus = computed(() =>
  props.menus.filter((item) => item.type !== 'button'),
)

function visibleChildren(item: AdminMenuRule) {
  return (item.children ?? []).filter((child) => child.type !== 'button')
}

function openMenu(item: AdminMenuRule) {
  if (item.name === 'user-detail') {
    router.push({ name: item.name, params: { id: 8 } })
    return
  }

  router.push({ name: item.name })
}
</script>
```

这个示例为动态参数提供了演示值 `8`。更通用的产品实现会把菜单目标与默认参数显式放进数据，而不是在组件中判断具体名称；本节先聚焦递归和状态，后续再抽象导航策略。

### 5.3 Aside 容器：`src/layouts/components/AdminAside.vue`

```vue
<template>
  <aside class="admin-aside" :style="{ width: sidebarWidth }">
    <el-button @click="appStore.toggleSidebar()">
      {{ sidebarActionText }}
    </el-button>

    <el-menu
      :default-active="activeMenu"
      :default-openeds="routeAncestorNames"
      :collapse="sidebarCollapsed"
    >
      <AdminMenuTree :menus="adminMenuRules" />
    </el-menu>
  </aside>
</template>

<script setup lang="ts">
import { computed } from 'vue'
import { storeToRefs } from 'pinia'
import { useRoute } from 'vue-router'
import AdminMenuTree from './AdminMenuTree.vue'
import { adminMenuRules, type AdminMenuRule } from '@/mock/adminMenu'
import { useAppStore } from '@/stores/app'

const route = useRoute()
const appStore = useAppStore()
const { sidebarCollapsed, sidebarWidth, sidebarActionText } = storeToRefs(appStore)

const activeMenu = computed(() => String(route.name ?? ''))

function findAncestors(
  nodes: AdminMenuRule[],
  target: string,
  ancestors: string[] = [],
): string[] | undefined {
  for (const node of nodes) {
    if (node.name === target) return ancestors
    const found = findAncestors(node.children ?? [], target, [...ancestors, node.name])
    if (found) return found
  }
}

const routeAncestorNames = computed(
  () => findAncestors(adminMenuRules, activeMenu.value) ?? [],
)
</script>
```

Element Plus 的 `default-openeds` 主要提供初始展开值。如果产品要求路由每次变化都强制同步展开，需要进一步使用受控的 `open`/`close` 事件、菜单实例方法，或用 `:key` 谨慎重建菜单。课堂中会通过实际版本行为选择最清楚的实现。

### 5.4 递归路由注册：`src/router/dynamic.ts`

```ts
export function registerDynamicRoutes(
  router: Router,
  rules: AdminMenuRule[],
): string[] {
  const registeredNames: string[] = []

  function visit(items: AdminMenuRule[]) {
    for (const rule of items) {
      if (rule.children?.length) visit(rule.children)

      if (
        rule.type !== 'menu' ||
        rule.menuType !== 'tab' ||
        !rule.component ||
        !rule.path ||
        router.hasRoute(rule.name)
      ) {
        continue
      }

      const viewComponent = viewComponents[rule.component]
      if (!viewComponent) {
        console.warn(`[dynamic-route] 找不到页面组件：${rule.component}`)
        continue
      }

      router.addRoute('admin', {
        path: rule.path,
        name: rule.name,
        component: viewComponent,
      })
      registeredNames.push(rule.name)
    }
  }

  visit(rules)
  return registeredNames
}
```

### 5.5 完整运行过程

访问 `/admin/users/8` 时：

1. Vue Router 匹配名为 `user-detail` 的动态路由。
2. `activeMenu` 从 `route.name` 得到 `user-detail`。
3. `findAncestors()` 在菜单树中找到祖先 `system` 和 `user-management`。
4. 最外层菜单展开祖先目录，并把 `user-detail` 标记为激活项。
5. `AdminMenuTree` 第一层渲染“系统管理”目录，递归实例渲染“用户管理”，第三层实例渲染“用户详情”叶子。
6. 刷新后点击历史消失，但 URL 仍恢复同一路由，所以高亮仍正确。

## 6. 常见错误

### 6.1 只写三层 `v-for`

手工嵌套三个循环只能支持恰好三层。菜单出现第四层就必须改模板。递归组件表达的是“任意层重复同一规则”。

### 6.2 没有终止条件

无论节点是否有孩子都渲染自身，会产生无限递归或空目录。必须在无可见 children 时进入叶子分支。

### 6.3 用标题或数组下标作为 key

标题可能重复、翻译或修改；下标会随排序变化。使用稳定唯一的业务标识。

### 6.4 高亮只在 click 时更新

程序化跳转、刷新、前进后退不会经过那个点击处理器。高亮应由当前路由推导。

### 6.5 动态路径直接和真实 URL 比较

规则 `users/:id` 不等于真实路径 `users/8`。使用路由 name，或让 Vue Router 完成路径解析，不要自己做脆弱字符串替换。

### 6.6 树形菜单出现了，但深层页面 404

菜单渲染已经递归，动态路由注册却仍只遍历第一层。两条消费链都必须能访问深层叶子。

### 6.7 把所有菜单状态放进 Pinia

是否折叠需要跨组件共享，适合 app store；当前激活项可以直接从 route 推导，不必复制进 store；仅服务于 Aside 的展开集合可以保留在菜单容器内。是否全局化取决于消费者和生命周期，而不是“它也是状态”。

### 6.8 递归数据形成环

正常 JSON 菜单是有限树。如果代码把祖先对象又塞回后代的 `children`，就形成环，递归不会终止。后端菜单也应保证节点关系无环；复杂系统可在转换时用 visited 集合防御异常数据。

## 8. 参考答案

1. 每层菜单节点结构相同，`children` 自引用可以表达任意深度；固定字段会限制层数并制造重复逻辑。
2. 当前节点没有可见子节点时，渲染叶子菜单项并停止递归。
3. 如果 children 全是按钮或隐藏项，视觉上它其实没有可展示子菜单；先过滤可避免渲染空目录。
4. route 是当前页面的事实来源，刷新、地址栏导航、程序化跳转、前进和后退都会更新 route，却不一定触发菜单点击。
5. `:id` 是参数占位符，`8` 是具体值；可使用稳定的 route name 或路由解析结果关联菜单。
6. 仅由菜单容器使用的展开交互可以留在 Aside；侧栏整体折叠会影响 Header、Aside 和布局宽度，适合 app store；激活项直接由 route 推导。
7. 原函数只看顶层规则，会漏掉目录 children 中的页面，导致菜单可见但路由没有注册。
8. `menuVertical.vue` 提供外层菜单、折叠和激活等状态；`menuTree.vue` 根据 children 递归渲染分支与叶子。
