# 第 09 节学习资料：Vue Router 基础

## 1. 学习目标

这份教材帮助你把第 08 节的单个登录页改造成一个真正可以导航的单页应用。读完并完成示例后，你应当理解：

- 浏览器地址、路由记录和 Vue 页面组件如何关联；
- `<RouterView>` 与 `<RouterLink>` 各自负责什么；
- 普通路由、重定向、嵌套路由、动态参数和 404 路由如何配置；
- `useRoute()` 与 `useRouter()` 为什么名字相似但职责不同；
- History 与 Hash 模式的直观区别；
- BuildAdmin 基础路由结构中哪些内容现在应该掌握。

## 2. 前置知识

### 2.1 单页应用不是只有一个“页面”

Vue 项目构建后，浏览器通常先加载同一个 HTML 入口。之后用户看到的登录页、首页、用户页，是 JavaScript 根据应用状态切换出来的组件。这类应用称为 SPA（Single Page Application，单页应用）。

“单页”是指主要只加载一个 HTML 外壳，并不是指整个产品只能有一个业务页面。

没有路由时，我们也能用变量切换组件：

```vue
<LoginView v-if="page === 'login'" />
<HomeView v-else-if="page === 'home'" />
```

但这种方式有明显问题：

- 地址栏不能表达用户在哪里；
- 刷新后很难恢复原页面；
- 无法方便地收藏或分享某个具体页面；
- 前进、后退难以与组件状态同步；
- 页面增多后，大量条件判断无法维护。

Vue Router 把“URL 与组件之间的映射”统一管理起来。

### 2.2 项目已经完成的注册步骤

练习项目的 `src/main.ts` 已有：

```ts
import router from './router'

const app = createApp(App)
app.use(router)
app.mount('#app')
```

`app.use(router)` 让整个 Vue 应用能够使用路由能力，包括 `<RouterView>`、`<RouterLink>`、`useRoute()` 和 `useRouter()`。

项目也已经安装 `vue-router`，所以今天无需重新安装依赖。

## 3. 核心概念

### 3.1 一次路由渲染经历什么

假设浏览器地址为 `/admin/users/8`：

1. Vue Router 读取当前 URL。
2. 它按路由表查找能够匹配该路径的记录。
3. `/admin` 匹配后台布局，`users/:id` 匹配用户详情组件。
4. 后台布局渲染到 `App.vue` 的 `<RouterView>`。
5. 用户详情渲染到后台布局自己的 `<RouterView>`。
6. 动态片段 `8` 被保存为参数 `route.params.id`。

因此路由不只是“跳转函数”，它还是 URL、组件层级和页面状态之间的协调者。

### 3.2 路由表

最小路由表如下：

```ts
import { createRouter, createWebHistory } from 'vue-router'
import LoginView from '@/views/login/LoginView.vue'

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    {
      path: '/login',
      name: 'login',
      component: LoginView,
    },
  ],
})

export default router
```

一条路由记录常见字段：

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `path` | 用于匹配 URL 的路径规则 | `/users/:id` |
| `name` | 路由的唯一名称，便于按名称导航 | `user-detail` |
| `component` | 匹配成功后渲染的组件 | `UserDetailView` |
| `redirect` | 匹配后跳到另一个位置 | `/login` |
| `children` | 需要渲染在父组件出口里的子路由 | 后台首页、用户页 |
| `meta` | 业务可读取的附加信息 | 标题、权限标识 |

`meta` 在成熟后台中很重要，但今天只需认识，第 10 节之后会继续使用。

### 3.3 RouterView：组件的路由出口

`App.vue` 可以极其简单：

```vue
<template>
  <RouterView />
</template>
```

访问 `/login` 时，这个位置显示登录组件；访问 `/admin` 时，这个位置显示后台布局。

RouterView 本身不决定显示谁。路由表和当前 URL 决定匹配结果，RouterView 只提供渲染位置。

### 3.4 RouterLink：声明式导航

```vue
<RouterLink to="/admin/home">首页</RouterLink>
```

它最终表现得像链接，但由 Vue Router 接管导航，通常不会重新加载整个应用。它适合菜单、面包屑和页面内明确可见的链接。

也可以按路由名称导航：

```vue
<RouterLink :to="{ name: 'user-detail', params: { id: 8 } }">
  查看用户 8
</RouterLink>
```

使用名称的好处是：以后路径结构调整时，调用方不一定需要跟着拼接字符串。

### 3.5 useRouter：发起编程式导航

提交按钮、保存成功回列表等场景，跳转发生在函数逻辑中：

```vue
<script setup lang="ts">
import { useRouter } from 'vue-router'

const router = useRouter()

function openUser() {
  router.push({ name: 'user-detail', params: { id: 8 } })
}
</script>

<template>
  <button @click="openUser">查看用户</button>
</template>
```

`router.push()` 会新增一条浏览历史，所以用户可以点击后退。`router.replace()` 会替换当前历史记录，常用于某些不希望用户返回的重定向场景。

### 3.6 useRoute：读取当前位置

用户详情页需要知道 URL 中的 ID：

```vue
<script setup lang="ts">
import { computed } from 'vue'
import { useRoute } from 'vue-router'

const route = useRoute()
const userId = computed(() => String(route.params.id ?? ''))
</script>

<template>
  <h1>用户 {{ userId }}</h1>
</template>
```

请用一句口诀区分：

- `route` 没有 `r` 结尾：当前这一个“位置对象”，用来读取 `path`、`params`、`query`、`meta`。
- `router` 有 `r` 结尾：控制整个“路由器”，用来 `push`、`replace`、`back`。

路由对象是响应式的。如果从 `/users/8` 导航到 `/users/9` 并复用同一个组件，使用 `computed` 或 `watch` 读取参数能正确跟随变化。不要只在初始化时把参数复制到普通常量后期待它自动更新。

### 3.7 动态参数与查询参数

动态参数写在路径结构里：

```ts
{ path: 'users/:id', name: 'user-detail', component: UserDetailView }
```

访问 `/admin/users/8` 时：

```ts
route.params.id // '8'
```

查询参数位于问号后，例如 `/admin/users?keyword=tom&page=2`：

```ts
route.query.keyword // 'tom'
route.query.page // '2'
```

一般来说，决定资源身份的值适合放动态参数，如用户 ID；筛选、排序、分页等可选条件适合放查询参数。

注意：从 URL 读取的值通常应先当作字符串处理。即使 URL 写的是 `8`，也不要直接假设它已经是 JavaScript 数字。

### 3.8 嵌套路由

后台系统通常有稳定布局：头部和侧栏不变，内容区随路由切换。父子路由正适合表达这种结构：

```ts
{
  path: '/admin',
  component: AdminLayout,
  children: [
    {
      path: '',
      redirect: '/admin/home',
    },
    {
      path: 'home',
      name: 'admin-home',
      component: HomeView,
    },
    {
      path: 'users/:id',
      name: 'user-detail',
      component: UserDetailView,
    },
  ],
}
```

子路由的 `path: 'home'` 不以 `/` 开头，它会和父路径组合为 `/admin/home`。若写成 `/home`，它会成为绝对路径，不再自然体现父子 URL 关系。

父组件必须提供子出口：

```vue
<template>
  <div class="admin-layout">
    <aside>后台菜单</aside>
    <main>
      <RouterView />
    </main>
  </div>
</template>
```

登录页不应成为 `/admin` 的子路由，因为它不需要后台侧栏与头部。把它放在顶层路由，组件结构就与视觉结构一致。

### 3.9 重定向与 404

根地址可以重定向到登录页：

```ts
{ path: '/', redirect: '/login' }
```

捕获未知路径：

```ts
{
  path: '/:pathMatch(.*)*',
  name: 'not-found',
  component: NotFoundView,
}
```

通配路由必须放在普通路由之后，避免阅读时造成误解。Vue Router 会进行路由匹配排序，但仍建议按照“具体到兜底”的顺序组织配置。

### 3.10 History 与 Hash 模式

练习项目当前使用：

```ts
createWebHistory(import.meta.env.BASE_URL)
```

地址类似：

```text
https://example.com/admin/home
```

它的 URL 更自然，但生产服务器必须把未知前端路径回退到 `index.html`。否则直接打开或刷新 `/admin/home` 时，服务器可能把它当作真实文件路径并返回 404。

BuildAdmin 使用：

```ts
createWebHashHistory()
```

地址类似：

```text
https://example.com/#/admin/home
```

井号后的部分不会作为普通资源路径发给服务器，因此部署配置通常更简单。两种模式不会改变路由表、RouterView 或导航的核心用法。

Vite 开发服务器通常能为 History 模式提供回退，所以本节应在开发环境验证刷新；正式部署时仍要记得服务器配置问题。

## 4. BuildAdmin 源码拆解

### 4.1 路由实例

目标文件：`buildadmin/web/src/router/index.ts`。

核心骨架可以压缩成：

```ts
const router = createRouter({
  history: createWebHashHistory(),
  routes: staticRoutes,
})
```

这说明 BuildAdmin 同样需要三样东西：路由器实例、历史模式和路由表。文件中还有 `beforeEach`、`afterEach`、进度条与语言包加载，它们属于后续课程，本节不要被这些代码干扰。

### 4.2 静态路由表

目标文件：`buildadmin/web/src/router/static.ts`。

你现在应该能认出这些基础结构：

- `/` 对应前台首页；
- 管理员登录页独立配置，不使用后台布局；
- 会员登录页也是独立页面；
- `/:path(.*)*` 捕获未知地址并转到 404；
- 路由组件使用 `() => import(...)` 延迟加载。

源码注释明确说明：管理员登录页不放在后台父路由的 `children` 中，因为登录页不需要后台布局。这正是本节嵌套路由要掌握的组件层级设计。

### 4.3 App.vue 是最外层出口

目标文件：`buildadmin/web/src/App.vue`。

忽略 Element Plus 全局配置后，核心就是：

```vue
<router-view></router-view>
```

BuildAdmin 的登录页、前台页面和后台布局都会先进入这个最外层出口。后台布局内部还有自己的 RouterView，用来承接后台子页面。

### 4.4 动态导入

BuildAdmin 写法：

```ts
component: () => import('/@/views/backend/login.vue')
```

这不是立刻导入组件，而是在需要该页面时再加载对应代码。练习项目可以写成：

```ts
component: () => import('@/views/login/LoginView.vue')
```

对于小项目，顶部静态导入也能工作；路由页面常用动态导入，是为了让初始代码包更小。今天可以使用动态导入，但重点仍是匹配关系，不是性能优化。

## 5. 完整示例与运行过程

下面是一个独立完整的最小示例，用来串起所有核心概念。它是教材示例；作业应在自己的现有登录页基础上完成。

### 5.1 `src/App.vue`

```vue

  <RouterView />
</template>
```

### 5.2 `src/router/index.ts`

```ts
import { createRouter, createWebHistory } from 'vue-router'

const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    {
      path: '/',
      redirect: '/login',
    },
    {
      path: '/login',
      name: 'login',
      component: () => import('@/views/login/LoginView.vue'),
    },
    {
      path: '/admin',
      component: () => import('@/layouts/AdminLayout.vue'),
      children: [
        {
          path: '',
          redirect: '/admin/home',
        },
        {
          path: 'home',
          name: 'admin-home',
          component: () => import('@/views/home/HomeView.vue'),
        },
        {
          path: 'users/:id',
          name: 'user-detail',
          component: () => import('@/views/user/UserDetailView.vue'),
        },
      ],

    {
      path: '/:pathMatch(.*)*',
      name: 'not-found',
      component: () => import('@/views/error/NotFoundView.vue'),
    },
  ],
})

export default router
```

在已有登录组件脚本中：

```ts
  router.push('/admin/home')
}
```

这只是演示导航。真实项目必须校验表单并等待登录成功后再跳转，后续课程会补齐。

### 5.8 运行过程

1. `npm run dev` 启动 Vite。
2. 浏览器访问 `/`，路由表将其重定向到 `/login`。
3. `App.vue` 的 RouterView 渲染登录组件。
4. 点击登录按钮，`router.push()` 把位置改为 `/admin/home`。
5. 顶层 RouterView 渲染 `AdminLayout`，布局内 RouterView 渲染 `HomeView`。
6. 点击“查看用户 8”，路由匹配 `users/:id`。
7. 用户详情组件从 `route.params.id` 读取字符串 `8`。
8. 访问未知地址时，通配路由渲染 404 页面。
9. 浏览器前进、后退时，Router 根据历史记录重新匹配并渲染对应组件。

## 6. 常见错误

### 错误一：App.vue 仍然固定渲染 LoginView

即使路由表配置正确，没有 RouterView 也无法显示匹配组件。根组件应交出页面渲染权：

```vue
<RouterView />
```

### 错误二：子路由匹配了，页面却不出现

通常是父组件 `AdminLayout.vue` 忘记添加自己的 `<RouterView />`。

### 错误三：子路由路径误写成绝对路径

```ts
children: [
  { path: '/home', component: HomeView },
]
```

前导 `/` 表示绝对路径。想得到 `/admin/home`，应写 `path: 'home'`。

### 错误四：混淆 useRoute 与 useRouter

```ts
const route = useRoute()
route.push('/home') // 错误：当前位置对象不负责导航
```

导航要用 `useRouter()` 返回的 Router 实例。

### 错误五：认为 ID 一定是 number

URL 参数通常是字符串。需要数值计算时应显式转换并验证：

```ts
const id = Number(route.params.id)
const isValidId = Number.isInteger(id) && id > 0
```

### 错误六：用普通 `<a href>` 或 location 完成内部跳转

它们可能让浏览器重新请求整个页面，丢失当前内存状态。应用内部导航优先使用 RouterLink 或 Router 实例。

### 错误七：忘记 404 路由

未知 URL 没有匹配记录时，RouterView 可能显示为空。通配路由应放在配置末尾，提供明确反馈。

### 错误八：History 模式部署后刷新 404

如果开发环境正常、部署后直接打开子路径失败，常见原因不是 Vue 路由表，而是服务器没有把未知路径回退到 `index.html`。

2. `app.use(router)`、路由表、`<RouterView>` 分别承担什么职责？
3. 为什么 `/admin/home` 通常设计为 `/admin` 的子路由？
4. 父路由与子路由各自对应哪个 RouterView？
5. `route.params.id` 与 `route.query.id` 分别来自什么样的 URL？
6. `useRoute()` 和 `useRouter()` 有什么区别？
7. 什么场景适合 RouterLink，什么场景适合 `router.push()`？
8. `router.push()` 与 `router.replace()` 对浏览历史有什么不同？

10. BuildAdmin 为什么把管理员登录页放在后台布局路由之外？

## 8. 参考答案

1. URL 能让页面可刷新恢复、可收藏分享，并让浏览器前进后退与页面切换保持一致。
2. `app.use(router)` 把 Router 安装进 Vue 应用；路由表声明 URL 与组件的映射；RouterView 提供匹配组件的渲染位置。
3. 后台首页需要复用后台头部、侧栏等布局；父子路由能让布局保持不变，只替换内部内容区。
4. `/admin` 的布局渲染到 `App.vue` 的 RouterView；`home` 等子页面渲染到 `AdminLayout.vue` 的 RouterView。
5. 动态参数来自类似 `/users/8` 且路径规则为 `/users/:id` 的 URL；查询参数来自类似 `/users?id=8` 的问号部分。
6. `useRoute()` 读取当前位置的数据；`useRouter()` 获得路由器实例，用于跳转、返回等操作。
7. 页面中可见且语义上是链接的导航适合 RouterLink；提交成功、按钮事件、条件判断后的跳转适合 `router.push()`。
8. `push` 新增历史记录，通常可以后退；`replace` 替换当前记录，不为这次位置变化新增一条可返回记录。
9. 浏览器刷新时服务器收到了具体子路径，但服务器没有对应真实文件，也没有配置回退到 SPA 的 `index.html`。
10. 登录页不需要后台头部与侧栏。放在父布局外能让路由层级与界面层级一致，避免在布局里额外判断隐藏区域。
