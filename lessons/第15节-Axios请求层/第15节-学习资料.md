# 第 15 节学习资料：Axios 请求层

## 1. 学习目标

学完本节后，你应能建立一个可复用的请求层：页面只表达“要什么数据”，API 模块描述“调用哪个业务接口”，Axios 客户端统一处理服务器地址、超时、请求头、响应解包和错误。你还应能用 TypeScript 泛型得到准确的数据类型，并理解如何取消已经没有意义的请求。

## 2. 前置知识

### 2.1 浏览器请求的输入、处理和输出

页面获取用户列表时，大致发生以下过程：

1. 页面调用 `getUsers({ page: 1 })`。
2. API 模块把它变成 `GET /api/users?page=1`。
3. 请求客户端补上 `baseURL`、超时和请求头。
4. 浏览器发送 HTTP 请求。
5. 服务器返回 HTTP 状态码和 JSON 响应体。
6. 响应拦截器检查并整理结果。
7. 页面拿到用户数组，更新 Vue 响应式状态，视图重新渲染。

Axios 不负责渲染页面，也不决定业务页面展示什么。它负责组织请求并把异步结果包装成 Promise。

### 2.2 Promise 与 `async/await`

请求不会立刻得到结果，因此返回 Promise：

```ts
async function loadUsers() {
  try {
    const result = await getUsers({ page: 1 })
    console.log(result.list)
  } catch (error) {
    console.error(error)
  }
}
```

`await` 等待 Promise 进入成功或失败状态。成功值赋给 `result`；`Promise.reject(...)` 会进入 `catch`。拦截器若把错误吞掉，页面会误以为请求成功，所以统一提示之后通常仍要 `return Promise.reject(error)`。

### 2.3 GET 的 `params`` 与 POST 的 `data`

Axios 中常见约定是：

```ts
http.get('/users', { params: { page: 1 } })
http.post('/users', { name: '小明' })
```

GET 的 `params` 会进入 URL 查询字符串，例如 `/users?page=1`。POST 的 `data` 通常进入请求体。这不是说 GET 永远不能有请求体，而是浏览器和服务端生态最常用、最容易互通的方式。

### 2.4 HTTP 状态与业务状态不是一回事

HTTP 状态描述传输层结果，例如 200、404、500。后端也可能始终返回 HTTP 200，但响应体是：

```json
{ "code": 0, "message": "账号已禁用", "data": null }
```

这叫业务失败。Axios 默认会把非 2xx 当作失败，却不知道项目规定 `code: 0` 是失败还是成功，所以业务状态必须由我们自己的响应拦截器判断。

## 3. 核心概念

### 3.1 为什么要分成三层

一个易维护的最小结构是：

```text
Vue 页面 → 业务 API 模块 → Axios 客户端 → 服务器
Vue 页面 ← 类型化业务数据 ← 统一解包/错误处理 ← 响应
```

页面负责 loading、数据显示和与用户交互；`api/users.ts` 负责用户业务的 URL、方法和参数；`utils/http.ts` 负责所有接口共同的传输规则。

如果页面直接散写 `axios.get('http://...')`，服务器地址、超时和 token 会重复。以后修改规则时容易漏改。反过来，也不应把“用户列表第几页”写死在公共客户端里，因为那属于具体业务。

### 3.2 Axios 实例

`axios.create()` 创建带默认配置的客户端：

```ts
import axios from 'axios'

export const http = axios.create({
  baseURL: '/api',
  timeout: 10_000,
  headers: { Accept: 'application/json' },
})
```

调用 `http.get('/users')` 时，`baseURL` 与相对地址组合为 `/api/users`。实例拥有自己的默认配置和拦截器，不污染其他 Axios 使用者。

### 3.3 请求拦截器

请求拦截器在请求发出前执行，常用于读取 token、补请求头或规范配置：

```ts
http.interceptors.request.use((config) => {
  const token = sessionStorage.getItem('token')
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config
})
```

拦截器必须返回 `config`，请求链才会继续。这里适合统一的 token 规则，不适合写某个页面的页码。

### 3.4 响应拦截器与统一解包

假设后端统一响应：

```ts
export interface ApiResponse<T> {
  code: number
  message: string
  data: T
}
```

`T` 是暂时留出的类型位置。若 `T` 是 `User[]`，那么 `data` 就是用户数组；若 `T` 是 `LoginResult`，`data` 就是登录结果。一个结构因此能描述许多接口。

可以在响应拦截器中检查业务状态：

```ts
http.interceptors.response.use(
  (response) => {
    const body = response.data
    if (body.code !== 1) return Promise.reject(new Error(body.message))
    return body.data
  },
  (error) => Promise.reject(error),
)
```

这样页面拿到的是业务数据，不必每次写 `response.data.data`。但这是一项项目约定，并非 Axios 的唯一正确用法。也可以保留完整响应；关键是团队保持一致，类型声明与运行时返回值一致。

### 3.5 泛型响应真正解决什么

```ts
interface User {
  id: number
  name: string
}

const users = await http.get<unknown, User[]>('/users')
users[0].name
```

这里第二个类型参数来自 Axios 方法的返回类型设计：由于本项目的响应拦截器直接返回业务数据，需明确告诉 TypeScript，最终 Promise 的值是 `User[]`。另一种更直白、也更容易维护的做法，是封装自己的泛型函数：

```ts
import type { AxiosRequestConfig } from 'axios'

export async function request<T>(config: AxiosRequestConfig): Promise<T> {
  return http.request<unknown, T>(config)
}
```

之后 API 模块写成：

```ts
export function getUsers() {
  return request<User[]>({ url: '/users', method: 'GET' })
}
```

泛型只帮助编译器检查，不会验证服务器真的返回了用户数组。如果后端返回的 JSON 与声明不一致，运行时仍可能出错。严格项目会再引入运行时数据校验，本节暂不展开。

### 3.6 取消请求

Axios 目前可使用浏览器标准 `AbortController`：

```ts
const controller = new AbortController()

getUsers({ page: 1 }, controller.signal)
controller.abort()
```

API 模块接收 `signal`：

```ts
export function getUsers(params: { page: number }, signal?: AbortSignal) {
  return request<User[]>({ url: '/users', method: 'GET', params, signal })
}
```

适用场景包括：组件离开后结果已经不需要；用户快速输入搜索词，旧搜索请求应停止；只允许最新一次请求更新页面。取消不会让服务器保证撤销已经开始的业务操作，因此不能用它代替“撤销订单”等业务接口。

## 4. BuildAdmin 源码拆解

本节以 `F:\project\MyProject\buildadmin` 中的实际源码为准。

### 4.1 总入口：`web/src/utils/axios.ts`

BuildAdmin 导出 `createAxios(axiosConfig, options, loading)`。业务 API 不直接在页面中配置完整请求，而是把 URL、method 和 data 交给这个函数。

函数内部每次调用 `axios.create()`，设置 `baseURL`、10 秒超时、语言头和 JSON 响应。随后安装请求与响应拦截器，最后执行 `Axios(axiosConfig)`。

它比本课最小实现复杂，因为成熟后台还处理：

- 管理端和用户端两套 token；
- token 过期刷新以及并发请求等待；
- Element Plus Loading 的并发计数；
- 业务成功、业务失败和 HTTP 错误提示；
- 重复请求识别和取消；
- 特殊业务码触发路由跳转；
- 是否返回精简响应的选项。

初学时不要逐行复制。先抓住稳定骨架：默认配置 → 请求拦截 → 发出请求 → 响应拦截 → 返回或 reject。

### 4.2 请求前发生什么

请求拦截器先处理 pending 请求，再按选项增加 Loading 计数，并从 store 读取 token 写入请求头。关键认识是：API 模块只说“调用登录接口”，统一客户端负责“当前 token 怎样带过去”。

### 4.3 响应后发生什么

响应成功回调先移除 pending 记录并关闭 Loading。当 JSON 中 `code !== 1` 时，它处理 token 刷新、提示或跳转，最后 `Promise.reject(response.data)`；业务成功时默认返回 `response.data`。HTTP 非 2xx、超时或网络异常进入第二个回调，统一提示后继续 reject。

因此页面可以用同一种 `try/catch` 接收业务失败与传输失败，同时公共层仍负责统一行为。

### 4.4 业务 API：`web/src/api/backend/index.ts`

`index()`、`login()` 和 `logout()` 只描述具体接口。例如 `login()` 把地址、method 和 data 交给 `createAxios()`。这正是业务 API 层：它知道“登录用哪个接口”，但不用重复写 baseURL、超时、token 和通用错误提示。

### 4.5 重复请求取消

源码使用 `pendingMap` 生成请求唯一 key，并使用 Axios 的旧式 `CancelToken` 取消相同的在途请求。我们会学习“为什么取消”，但练习优先采用标准 `AbortController`。二者实现不同，解决的核心问题相似：避免旧请求继续占用资源或用过时结果覆盖新结果。

## 5. 完整示例与运行过程

下面是可独立理解的最小示例。它使用 `axios-mock-adapter` 在浏览器内模拟服务器，仅作为教材参考；课堂实践会根据当前项目逐步完成，不要求一次抄完。

### 5.1 安装与文件结构

│   └── http.ts
└── views/

### 5.2 `src/api/types.ts`

```ts
export interface ApiResponse<T> {
  code: number
  message: string
  data: T
}

export interface User {
  id: number
  name: string
}
```

### 5.3 `src/utils/http.ts`

```ts
import axios from 'axios'
import type { AxiosRequestConfig } from 'axios'
import type { ApiResponse } from '../api/types'

export const http = axios.create({
  baseURL: '/api',
  timeout: 10_000,
})

http.interceptors.request.use((config) => {
  const token = sessionStorage.getItem('token')
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config
})

http.interceptors.response.use(
  (response) => {
    const body = response.data as ApiResponse<unknown>
    if (body.code !== 1) return Promise.reject(new Error(body.message))
    return body.data
  },
  (error) => Promise.reject(error),
)

export function request<T>(config: AxiosRequestConfig): Promise<T> {
  return http.request<unknown, T>(config)
}
```

### 5.4 `src/api/users.ts`

```ts
import { request } from '../utils/http'
import type { User } from './types'

export interface UserQuery {
  page: number
}

export function getUsers(params: UserQuery, signal?: AbortSignal) {
  return request<User[]>({ url: '/users', method: 'GET', params, signal })
}
```

### 5.5 `src/mock/httpMock.ts`

```ts
import MockAdapter from 'axios-mock-adapter'
import { http } from '../utils/http'

const mock = new MockAdapter(http, { delayResponse: 600 })

mock.onGet('/users', { params: { page: 1 } }).reply(200, {
  code: 1,
  message: 'ok',
  data: [
    { id: 1, name: '小明' },
    { id: 2, name: '小红' },
  ],
})
```

在 `src/main.ts` 启动应用前导入一次：

```ts
import './mock/httpMock'
```

模拟器拦截当前 Axios 实例的请求，所以不需要真实后端。它返回的结构仍会经过响应拦截器。

### 5.6 `src/views/UserListView.vue`

```vue
<script setup lang="ts">
import { onBeforeUnmount, onMounted, ref } from 'vue'
import { getUsers } from '../api/users'
import type { User } from '../api/types'

const users = ref<User[]>([])
const loading = ref(false)
const errorMessage = ref('')
const controller = new AbortController()

async function loadUsers() {
  loading.value = true
  errorMessage.value = ''
  try {
    users.value = await getUsers({ page: 1 }, controller.signal)
  } catch (error) {
    if (error instanceof Error && error.name !== 'CanceledError') {
      errorMessage.value = error.message
    }
  } finally {
    loading.value = false
  }
}

onMounted(loadUsers)
onBeforeUnmount(() => controller.abort())
</script>

<template>
  <p v-if="loading">正在加载...</p>
  <p v-else-if="errorMessage">{{ errorMessage }}</p>
  <ul v-else>
    <li v-for="user in users" :key="user.id">{{ user.name }}</li>
  </ul>
</template>
```

### 5.7 实际运行过程

1. 页面挂载，`loadUsers()` 将 loading 设为 true。
2. `getUsers()` 将页码交给 `request<User[]>()`。
3. Axios 合并 baseURL，得到 `/api/users?page=1`。
4. 请求拦截器检查 token，然后模拟服务器在 600ms 后返回 JSON。
5. 响应拦截器看到 `code === 1`，只返回 `data`。
6. `users.value` 得到带类型的数组，Vue 渲染“小明、小红”。
7. 若 600ms 内离开页面，卸载钩子调用 `abort()`；取消错误不会显示成普通失败。

## 6. 常见错误

### 6.1 创建了实例，业务代码却还使用全局 `axios`

拦截器装在 `http` 实例上。若写 `axios.get(...)`，这些配置不会生效。业务 API 应统一调用 `http` 或封装后的 `request()`。

### 6.2 忘记返回 config 或 response

拦截器属于 Promise 链。成功回调不返回值，下一环拿到的就是 `undefined`；请求拦截器不返回 config，请求也无法正常继续。

### 6.3 统一提示后吞掉错误

```ts
(error) => {
  showMessage(error)
}
```

这样可能使调用方无法进入 `catch`。应该在提示后 `return Promise.reject(error)`。

### 6.4 把 TypeScript 类型当作运行时验证

`request<User[]>()` 不会检查 JSON。它只是开发期间的约定和检查。若接口不可信，需要额外的运行时校验。

### 6.5 把业务参数放进公共客户端

baseURL、超时和 token 是共性；用户页页码、搜索词是业务输入。后者应由页面传给对应 API 函数。

### 6.6 把所有失败都叫“网络错误”

业务失败、HTTP 500、超时、主动取消含义不同。用户提示和程序处理应按类型区分。本节先建立边界，第 18 节会系统完成错误反馈。

### 6.7 用取消请求代替业务撤销

`abort()` 只停止客户端等待或传输，服务器可能已经执行操作。涉及付款、删除、发货等操作，必须由后端提供幂等或撤销机制。

## 8. 参考答案

1. `/users` 是用户业务的接口知识，业务变化时由用户 API 模块维护；baseURL 是全部请求共享的传输配置，应集中管理。这样页面、业务和公共规则各自只承担一种职责。
2. 请求拦截器在浏览器发出请求前运行，可补 token 和整理配置；响应拦截器在收到响应或发生传输错误后运行，可解包数据、判断业务码并统一处理错误。
3. 不能。HTTP 200 只说明 HTTP 传输层成功，响应体仍可能通过 `code` 表示账号禁用、参数不正确等业务失败。
4. 公共层可以统一展示信息，但具体页面仍需停止成功流程、关闭 loading 或恢复交互。继续 reject 才能让调用方的 `catch` 得知失败。
5. 不能。泛型只在编译时告诉 TypeScript 我们预期的结构，不会在浏览器运行时验证 JSON。
6. 旧搜索结果可能比新结果更晚返回，从而用过时结果覆盖最新页面；旧请求也会浪费资源。取消旧请求可让最新输入成为唯一有效请求。
7. 实例拥有自己的 baseURL、timeout 和拦截器。直接调用全局 axios 会绕过装在实例上的规则，导致 token、解包或统一错误处理不生效。
