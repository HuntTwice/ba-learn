### 动手任务 2：修正纵向高度与滚动边界

学生提问：“往外我页面为什么没有滚动条，按理来说应该溢出了”。

Coach 解释：尺寸基准确实是 Header `50px` 加上 Body `100%`，但二者都是纵向 Flex 子项，默认 `flex-shrink: 1`。当它们的基准尺寸总和超过父容器时，浏览器会按收缩因子压缩二者，使最终总高度重新等于父容器，所以不一定出现外层滚动条。副作用是 Header 声明的 `height: 50px` 不再保证最终计算高度恰好为 50px。若临时将两个子项都设为 `flex-shrink: 0`，尺寸才会按声明值相加并明显溢出；这只用于理解，不是最终方案。

本任务修改 `src/layouts/AdminLayout.vue`：

1. `.title` 使用 `flex: 0 0 50px`，明确固定高度且不收缩。
2. `.container` 删除 `height: 100%`，改为 `flex: 1` 和 `min-height: 0`，只占 Header 之外的剩余高度。
3. `.main` 删除 `height: 100%`，增加 `min-width: 0`、`min-height: 0` 和 `overflow: auto`，成为业务内容滚动区。
4. `.admin` 增加 `overflow: hidden`，避免整个后台外壳滚动。
5. 清理仍遗留在 `AdminLayout.vue` 中且未使用的 `useAppStore` 导入。

完成标志：Header 保持 50px，Body 自动占据其余高度；业务内容过长时 Main 内部滚动，布局外壳不滚动。

阶段检查（2026-08-29）：

- 已完成：`.admin` 增加 `overflow: hidden`；`.title` 使用 `flex: 0 0 50px`；`.container` 使用 `flex: 1`；未使用的 `useAppStore` 已清理。
- Coach 执行 `npm.cmd run type-check`，检查通过。
- 尚未完成：`.container` 缺少 `min-height: 0`；`.main` 仍保留 `height: 100%`，且缺少 `min-width: 0`、`min-height: 0`。
- 核心反馈：`overflow: auto` 只有在 Main 被允许收缩到分配空间时才能可靠形成内部滚动区。Flex 子项默认的最小尺寸可能由内容决定，因此需要显式将最小尺寸设为 `0`。

学生追问：“我不是很理解 `.container { min-height: 0 }` 和 `.main { min-width: 0; min-height: 0 }` 这两个是什么意思”。

Coach 补充讲解：

- `min-height: 0` 不是把实际高度设为 0，而是把“允许缩到的最小高度”设为 0；实际高度仍由 `flex: 1` 分配。
- `.container` 是纵向 `.admin` 的 Flex 子项。默认 `min-height: auto` 时，它可能把内部内容高度当成自己的最低高度，从而拒绝缩进 Header 之外的剩余空间。设置 `min-height: 0` 后，它可以保持在剩余空间内，让内部滚动区处理超长内容。
- `.main` 是横向 `.container` 的 Flex 子项。默认 `min-width: auto` 时，一张很宽的表格或长字符串可能成为 Main 的最低宽度并撑破布局；`min-width: 0` 允许 Main 保持在侧栏之外的剩余宽度，溢出内容交给自身滚动或换行规则处理。
- 本结构中 `.main { min-height: 0 }` 是明确滚动边界的防御性规则，尤其在 Main 内继续嵌套 Flex 容器时有用；当前最关键的是 Container 的 `min-height: 0` 和 Main 的 `min-width: 0`。
- 删除 `.main { height: 100% }` 是因为 Container 已有确定的剩余高度，横向 Flex 默认的 `align-items: stretch` 会让 Main 自动铺满高度；百分比高度属于重复约束。

学生进一步理解：“`min-height` 只是用来重置 Flex 带来的副作用，实际 `min-height: 2px` 也可以”。

Coach 反馈：方向接近，但需更精确。这里是在覆盖 Flex 子项的“自动最小尺寸”规则，而不是修复 Flex 的普通副作用。`min-height: 2px` 的确也允许元素比内容高度更小，在通常尺寸下可能看起来与 `0` 相同；但它仍规定元素绝不能低于 2px。当可分配空间小于 2px，或布局嵌套产生极端约束时，仍可能贡献溢出。`0` 准确表达“本组件不额外规定最低高度，完全服从 Flex 分配”，没有任意的魔法数，因此是滚动型 Flex 布局的惯用值。

学生继续追问：`.main` 所在父容器的主轴是 X 轴，`min-width: 0` 已处理主轴最小尺寸，那么 `min-height: 0` 有什么作用。

Coach 修正与反馈：学生判断正确。应当从元素作为父级 Flex 子项时的主轴分析：

- `.container` 是纵向 `.admin` 的子项，其父级主轴为 Y，因此 `.container { min-height: 0 }` 是关键规则。
- `.main` 是横向 `.container` 的子项，其父级主轴为 X，因此 `.main { min-width: 0 }` 是关键规则。
- 在当前这一级结构中，`.main { min-height: 0 }` 不是解决 Flex 主轴自动最小尺寸所必需的，可以省略；Main 会在父级交叉轴上默认 stretch，并由 `overflow: auto` 处理内容。
- 只有当 Main 自己处于另一个纵向 Flex 分配链中，或其内部再建立需要收缩的纵向 Flex 子区域时，相关层级的 `min-height: 0` 才会再次成为关键。

Coach 对先前说法作出澄清：将 `.main { min-height: 0 }` 称为本结构的必要滚动边界规则过于泛化。本项目当前应保留 `.container { min-height: 0 }` 与 `.main { min-width: 0 }`，无需为了模板化写法强制添加 Main 的 `min-height: 0`。

最终检查（2026-08-29）：

- `.container` 已使用 `flex: 1; min-height: 0`，正确占据固定 Header 之外的剩余高度。
- `.main` 已删除 `height: 100%`，使用 `flex: 1; min-width: 0; overflow: auto`。
- 学生能根据父级主轴方向判断应重置 `min-height` 还是 `min-width`，而非机械套用规则。
- Coach 再次执行 `npm.cmd run type-check`，检查通过。

本节从已有单文件布局出发，完成了 Header、Aside、Main 的职责拆分，并建立了稳定的 Flex 尺寸链。学生不仅实现了布局，还通过反向实验理解了以下关键点：

1. `flex: 1` 分配的是父容器主轴上的剩余空间。
2. Flex 子项的自动最小尺寸可能阻止它按剩余空间收缩；应根据父级主轴选择 `min-height: 0` 或 `min-width: 0`。
3. `overflow: hidden` 只裁剪外溢，不能代替正确的尺寸分配。
4. `overflow: auto` 应放在真正承担滚动责任的 Main。
5. 对超长内容强制 Flex 居中可能产生不可到达的负方向溢出。
6. scoped 样式应跟随对应 DOM 迁移到职责所属组件。
7. 练习布局与 BuildAdmin 默认布局排列不同，但都通过布局内 `RouterView` 承载子路由页面。

非阻塞代码清理建议：`AdminMain.vue` 的空 `<script setup>` 可以删除；当前 `display: flex` 若没有具体布局用途也可以删除。它们不影响本节核心验收。
