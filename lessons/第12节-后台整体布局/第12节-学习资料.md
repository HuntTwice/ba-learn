# 第 12 节学习资料：后台整体布局

## 1. 学习目标

学完本资料后，你应能独立搭建 Vue 后台的页面骨架，理解布局为什么需要单独存在，正确组合 Header、Aside、Main 与 `RouterView`，并能读懂 BuildAdmin 默认后台布局的核心结构。

## 2. 前置知识

### 2.1 布局与业务页面不是一回事

后台系统通常有两类界面：

- 布局：顶部栏、侧边栏、内容容器，切换业务页面时通常继续存在。
- 页面：首页、用户详情、订单列表等，会随着当前路由变化。

若当前地址从 `/admin/home` 变成 `/admin/users/8`，理想结果是外层后台壳子保持，只有主内容区切换。这既避免重复代码，也为菜单、用户信息和标签页提供稳定的容器。

### 2.2 嵌套路由与 RouterView

简化路由表如下：

```ts
const routes = [
  {
    path: '/admin',
    component: () => import('@/layouts/AdminLayout.vue'),
    children: [
      { path: 'home', component: () => import('@/views/home/HomeView.vue') },
      { path: 'users/:id', component: () => import('@/views/user/UserDetailView.vue') },
    ],
  },
]
```

访问 `/admin/home` 时，Vue Router 先渲染 `AdminLayout.vue`。布局中的 `RouterView` 再渲染 `HomeView.vue`。因此布局是父级路由组件，业务页面是子级路由组件。

### 2.3 Flexbox 的三个必要概念

后台骨架最常用 Flexbox：

- `display: flex`：让直接子元素进入弹性布局。
- `flex-direction`：决定主轴是横向还是纵向。
- `flex: 1`：让元素占据扣除固定尺寸后的剩余空间。

`flex: 1` 的价值是让剩余空间随窗口和侧栏宽度自动变化，不需要在 JavaScript 中反复计算主区域宽度。

### 2.4 百分比高度为什么经常失效

`height: 100%` 依赖父元素拥有可计算的明确高度。如果 `html`、`body`、`#app` 中某一层没有高度，子元素的 `100%` 可能没有预期效果。

后台根布局可以使用：

```css
html,
body,
#app {
  width: 100%;
  height: 100%;
  margin: 0;
}
```

或者根布局使用 `min-height: 100vh`。二者侧重点不同：固定视口高的后台应用常让内部 Main 滚动；普通内容网站更常允许整个文档自然增长。

## 3. 核心概念

### 3.1 三层结构

一种常见结构是“顶部栏跨整页”：

```text
AdminLayout（纵向）
├── AdminHeader（固定高度）
└── Body（横向、占剩余高度）
    ├── AdminAside（固定或可折叠宽度）
    └── AdminMain（占剩余宽高）
```

对应 CSS：

```css
.layout {
  height: 100vh;
  display: flex;
  flex-direction: column;
  overflow: hidden;
}

.layout-body {
  min-height: 0;
  flex: 1;
  display: flex;
}

.layout-main {
  min-width: 0;
  min-height: 0;
  flex: 1;
  overflow: auto;
}
```

`min-height: 0` 很关键。Flex 子项默认可能不愿小于内容本身的最小高度，造成外层被内容撑开。设为 `0` 后，Main 才能在分配到的空间内滚动。横向内容同理使用 `min-width: 0`。

### 3.2 尺寸的事实来源

侧栏只需要保存“是否折叠”这个事实：

```ts
const sidebarCollapsed = ref(false)
const sidebarWidth = computed(() =>
  sidebarCollapsed.value ? '64px' : '220px',
)
```

不要同时独立保存 `collapsed`、`width` 和按钮文字，否则一次折叠需要同步修改多份数据。宽度和按钮文字都应该由折叠状态计算。

### 3.3 组件职责

- `AdminLayout`：组合区域，不关心某个具体页面的业务。
- `AdminHeader`：显示头部内容，提供折叠、账户等全局入口。
- `AdminAside`：显示品牌和菜单，消费侧栏宽度状态。
- `AdminMain`：提供子路由出口，控制内容背景、内边距与滚动。
- 页面组件：实现首页、用户等业务，不控制整个后台壳子的尺寸。

拆分组件不是为了让文件越多越好，而是让变化原因分离。第 13 节递归菜单主要修改 Aside，第 14 节标签页主要扩展 Header/Main，布局骨架因此不必反复重写。

### 3.4 DOM 结构比视觉标签更重要

Element Plus 的 `el-container`、`el-header`、`el-aside` 和 `el-main` 能表达布局语义，但本质仍是组件和 CSS。原生 `div` 配合 Flexbox 也能完成同样布局。学习重点是尺寸关系、组件职责和滚动边界，而不是记住某一组标签。

## 4. BuildAdmin 源码拆解

### 4.1 布局入口：动态选择容器

`web/src/layouts/backend/index.vue` 使用动态组件：

```vue
<component :is="config.layout.layoutMode"></component>
```

BuildAdmin 支持 Default、Classic、Streamline、Double 等布局模式，所以入口负责根据配置选容器。练习项目当前只需完成一种稳定布局，不必提前复制多布局复杂度。

这个入口还承担后台初始化和响应式布局切换。窗口较窄时，它切换布局模式并收起菜单。这里说明成熟后台的布局入口也可能承担“选择布局和协调初始化”，但具体视觉区域仍由子组件负责。

### 4.2 默认容器：组合三大区域

`web/src/layouts/backend/container/default.vue` 的核心结构是：

```vue
<el-container class="layout-container">
  <Aside />
  <el-container class="content-wrapper">
    <Header />
    <Main />
  </el-container>
</el-container>
```

这里采用“侧栏贯穿全高，右侧再纵向放 Header 与 Main”的结构：

```text
Default Container（横向）
├── Aside
└── Content Wrapper（纵向）
    ├── Header
    └── Main
```

它和“Header 跨整页”的方案都合理，只是视觉结构不同。学习时应先看 DOM 的父子与主轴关系，再看颜色和间距。

### 4.3 Header 的职责

BuildAdmin 的 `components/header.vue` 不直接堆放所有按钮，而是根据布局模式选择相应 NavBar：

```vue
<component :is="config.layout.layoutMode + 'NavBar'"></component>
```

这是一种配置驱动的扩展设计。我们的单布局练习不需要动态组件，但可以保持 Header 独立，为后续账户菜单、主题切换和标签页留出位置。

### 4.4 Aside 的职责

BuildAdmin 的 `components/aside.vue` 组合 Logo 和菜单，并通过配置 store 得到菜单宽度。其样式为不同布局模式定义不同间距、高度和定位方式。

值得学习的是：

1. 折叠事实属于全局配置 store。
2. Aside 消费派生宽度并负责自己的视觉表现。
3. 菜单渲染被继续拆给菜单组件。
4. 小屏幕时可以通过定位与遮罩形成抽屉式侧栏。

### 4.5 Main 是真正的业务出口

主区域最终需要承载当前子路由。布局不应写死 `<HomeView />`，而应放置 `RouterView`。这样路由表决定当前业务页面，布局只提供显示空间。

### 5.5 运行过程

访问 `/admin/home` 时：

1. 路由匹配父级 `/admin`，创建 `AdminLayout`。
2. Layout 创建 Header、Aside 和 Main。
3. Main 内的 `RouterView` 匹配子级 `home`，渲染首页。
4. 点击用户菜单后，父级布局仍匹配，Main 中的子页面切换。
5. 点击折叠按钮，Pinia action 改变 `sidebarCollapsed`。
6. `sidebarWidth` 与按钮文字重新计算。
7. Aside 宽度产生过渡，Main 通过 `flex: 1` 自动占据新的剩余空间。

示例是完整参考，不代表课堂一开始就照抄。动手阶段会根据当前代码逐步重构，并要求你解释每一步解决的问题。

## 6. 常见错误

### 6.1 Header 与 `height: 100%` 的 Body 相加溢出

纵向 Flex 容器中，Header 已占固定高度，Body 再写 `height: 100%`，两者可能超过父容器。更稳妥的是 Header 固定高度，Body 使用 `flex: 1; min-height: 0`。

### 6.2 Main 写死宽度

侧栏会折叠，窗口也会变化。Main 写死 `width: 1000px` 或用 JavaScript 计算宽度都不灵活。让侧栏提供宽度，Main 使用 `flex: 1`。

### 6.3 RouterView 放错层级

如果根 `App.vue` 有 `RouterView`，它负责渲染顶层路由；`AdminLayout` 内还必须有一个 `RouterView` 承载它的 children。缺少第二层出口时，地址变化但子页面不会显示。

### 6.4 所有区域一起滚动

后台通常希望 Header 和 Aside 保持可见，只有 Main 内容滚动。根布局使用 `overflow: hidden`，Main 使用 `overflow: auto`，并确保 Flex 子项可收缩。

### 6.5 重复定义侧栏宽度

如果 store、模板内联样式和 CSS 各写一个宽度，它们很容易冲突。将折叠状态作为事实来源，通过 computed 得到宽度，再由 Aside 消费。

### 6.6 为拆分而拆分

只有几行且没有独立职责的包装组件可能增加跳转成本。Header、Aside、Main 值得拆，是因为它们的内容、样式和后续变化方向明显不同。

### 6.7 折叠后只缩宽度，不处理内容

文字仍可能溢出或挤压。可以隐藏菜单文字、使用图标、设置 `white-space: nowrap` 与 `overflow: hidden`。第 13 节会进一步处理菜单呈现。

## 7. 自测题

1. 后台布局与用户列表页面的生命周期和职责有什么区别？
2. 为什么后台布局内还需要一个 `RouterView`？
3. Header 固定为 56px 后，Body 为什么推荐 `flex: 1` 而不是 `height: 100%`？
4. `min-height: 0` 在纵向 Flex 布局中解决什么问题？
5. 哪个区域通常负责滚动？为什么？
6. 侧栏宽度为什么适合作为 getter/computed？
7. BuildAdmin 默认容器的结构与“Header 跨整页”的结构有什么区别？
8. 为什么本节不需要立即复刻 BuildAdmin 的四种布局模式？

## 8. 参考答案

1. 布局是多个后台页面共享的稳定外壳；用户列表是随子路由切换的业务页面。布局负责区域组织，页面负责具体业务。
2. 顶层 `RouterView` 渲染父路由布局，布局内的 `RouterView` 才能渲染当前匹配的子路由页面。
3. `height: 100%` 未扣除 Header，可能造成总高度溢出；`flex: 1` 会自动取得固定 Header 之外的剩余空间。
4. 它允许 Flex 子项小于其内容的默认最小高度，从而在分配空间内正确滚动，不把外层容器撑开。
5. 通常是 Main，因为 Header 和导航需要持续可见，业务内容长度最不确定。
6. 真正的源状态是是否折叠，宽度能从该布尔值确定；计算可避免两份状态不同步。
7. BuildAdmin 默认布局让 Aside 贯穿左侧全高，右侧纵向排列 Header 和 Main；另一方案让 Header 位于整页顶部，下面横向排列 Aside 和 Main。
8. 当前目标是掌握一种布局的核心尺寸关系和职责边界；多布局是同一基础上的产品扩展，过早复制会掩盖核心原理。
