先补提交前的一步：**前端表单校验**。例如账号没填、密码长度不够，可以直接提示用户。它检查输入是否符合规则；账号密码是否匹配，仍由服务端判断。

Element Plus 的校验需要把这几处连起来：

- `model`：表单数据，你已有 `form`。
- `rules`：字段的校验规则。
- `prop`：表单项对应的字段名，例如 `prop="username"`。
- `formRef`：取得表单组件实例，提交时调用它的 `validate()`。

例如账号规则可以这样写：

```ts
import type { FormInstance, FormRules } from 'element-plus'

const formRef = ref<FormInstance>()
const rules: FormRules = {
  username: [
    { required: true, message: '请输入账号', trigger: 'blur' },
  ],
}
```

`required` 表示必填，`blur` 表示失去焦点时检查。表单上绑定 `ref="formRef"` 和 `:rules="rules"`，账号的 `el-form-item` 上绑定 `prop="username"`，这条规则才能对应到账号输入。

### 2026-09-03：补充问答——el-form 的 model 与输入框 v-model

学生分享问答来源：[解释el form model作用](chatgpt-conversation://6a992b9d-857c-83ee-a79a-2968564cddd7)。以下按本次提供的完整预览原文归档。

引用中的学生问题原文：

elform的model有什么用，输入框不是通过v-model绑定了form的属性吗，为什么还需要elform的model属性

引用中的回答原文：

可以把它理解成：

**`el-input` 的 `v-model` 管“这个输入框的值”，`el-form` 的 `model` 管“整张表单的数据”。**

比如：

```vue
<el-form :model="form">
  <el-form-item label="用户名" prop="username">
    <el-input v-model="form.username" />
  </el-form-item>

  <el-form-item label="密码" prop="password">
    <el-input v-model="form.password" />
  </el-form-item>
</el-form>
```

这里有两层作用。

### 1. `v-model="form.username"`：负责输入框的数据同步

你输入：

```text
张三
```

实际上就是：

```js
form.username = '张三'
```

所以即使你把 `el-form` 的 `model` 删掉：

```vue
<el-form>
  <el-input v-model="form.username" />
</el-form>
```

**输入框照样能正常输入，`form.username` 也照样会变。**

---

### 2. `:model="form"`：告诉 `el-form` 整张表单的数据在哪里

`el-form` 自己并不知道：

```js
form.username
form.password
```

这些输入框到底属于哪个对象。

所以你告诉它：

```vue
<el-form :model="form">
```

意思就是：

> 这张表单的数据对象就是 `form`。

这样 `el-form` 才能配合：

```vue
prop="username"
```

找到：

```js
form.username
```

然后完成**表单校验、重置等功能**。

比如：

```vue
<el-form
  ref="formRef"
  :model="form"
  :rules="rules"
>
  <el-form-item
    label="用户名"
    prop="username"
  >
    <el-input v-model="form.username" />
  </el-form-item>
</el-form>
```

这里三者的关系就是：

```text
:model="form"
       ↓
整个表单的数据

prop="username"
       ↓
告诉 el-form-item：我对应 form.username

v-model="form.username"
       ↓
输入框真正修改 form.username
```

所以可以记成一句话：

```text
el-input 的 v-model：负责改数据

el-form 的 model：负责让表单组件认识这份数据
```

为什么 `el-form` 要认识数据？

因为你后面会用：

```js
formRef.value.validate()
formRef.value.resetFields()
```

例如 `resetFields()` 要把：

```js
form.username
form.password
```

恢复初始值。

那 `el-form` 必须先知道**你的表单对象是哪个**，所以才需要：

```vue
:model="form"
```

最简单的理解：

```text
v-model = 输入框和数据之间的线

:model = 把整份数据交给 el-form 管理
```

因此，**只需要输入数据时，`el-form` 的 `model` 看起来确实没什么作用；一旦你使用表单校验、resetFields 等功能，它就很重要了。**

本课堂 Coach 完整回答：

这段解释抓住了核心：**输入框知道自己绑定哪个值，但外层表单不会自动从输入框的 `v-model` 推断出整份数据。**

所以需要两条连接：

- `v-model="form.username"`：让输入框读写 `form.username`。
- `:model="form"` 配合 `prop="username"`：让表单找到需要校验的 `form.username`。

### 2026-09-03：为什么模板 ref 不需要动态绑定

学生原问题：

> 为什么ref不需要使用动态绑定，就可以直接使用

Coach 完整回答：

因为 **`ref` 是 Vue 的特殊属性，它支持用一个固定名称登记组件引用**。这里不需要读取变量的当前值，所以不用加冒号。

先看普通属性的区别：

```vue
<el-form model="form" />
<el-form :model="form" />
```

- `model="form"`：传入字符串 `"form"`。
- `:model="form"`：执行表达式 `form`，传入那个表单数据对象。

而你写的：

```vue
<script setup lang="ts">
import { ref } from 'vue'
import type { FormInstance } from 'element-plus'

const formRef = ref<FormInstance>()
</script>

<template>
  <el-form ref="formRef" />
</template>
```

这里的 `ref="formRef"` 可以理解为告诉 Vue：

> 这个组件的引用叫 formRef。组件挂载后，请把它的实例放到对应的引用变量里。

因此过程是：

```ts
// 组件挂载前
formRef.value // undefined

// 组件挂载后，Vue 自动设置引用
formRef.value // el-form 的组件实例
```

随后你才能调用：

```ts
formRef.value.validate()
```

**两者的数据方向不同：**

- `:model="form"`：你把已有的数据对象传给表单。
- `ref="formRef"`：你指定引用名称，Vue 把创建好的表单实例交给你。

所以，“不加冒号是固定内容，加冒号是表达式”这个规则并没有失效。只是 **Vue 对 `ref` 这个特殊属性，定义了“按名称建立引用”的处理方式**。

另外，脚本中的 `ref()` 是创建响应式容器的函数，模板中的 `ref="..."` 是登记引用的特殊属性；它们名字相同，但不是同一个东西。这里通过同名的 `formRef` 配合使用。

`ref` 也支持 `:ref="..."`，例如绑定一个接收实例的函数；但那是另一种用法，不需要为了“连接变量”就给当前写法加冒号。

核对依据：本地 Vue runtime-core 的 setRef 包含字符串引用登记、setup 状态赋值与 ref 对象赋值分支。当前仍等待任务一实现，未新增编码任务或判定代码通过。

const userStorageKey = 'ba-learn-user'

- 理解验收：校验与认证、凭证读写一致性、刷新恢复、本地 token 与服务器认证边界均通过。

## 9. 学习小结

本节从“点击按钮直接跳转”改造成完整的登录数据流。页面负责表单与交互，auth API 负责登录请求，user store 负责共享身份，请求拦截器负责携带 token，持久化插件负责刷新恢复。学生主动识别手写双存储对于当前目标过度展开，课程调整为 BuildAdmin 采用的插件思路。
