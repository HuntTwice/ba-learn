# 第 16 节学习资料：登录页与登录状态

## 1. 学习目标

学完本节，你应能把“点击按钮就跳转”的静态登录页改造成一条有结果判断的流程：读取账号密码 → 校验输入 → 等待登录结果 → 成功后保存身份并跳转，失败时留在登录页并给出提示。

你还应能解释密码、token、用户信息分别是什么，以及为什么保存到 Pinia 的数据通常会在刷新后消失。本节建立登录状态；第 17 节再用路由守卫控制后台访问并处理登录恢复，第 18 节系统整理请求错误与反馈。

## 2. 前置知识

### 2.1 表单模型就是输入值的集合

```ts
const form = reactive({ username: '', password: '' })
```

`form` 是响应式对象。`v-model="form.username"` 把输入框与账号字段双向连接：输入改变字段，代码修改字段也会改变输入框。密码框的 `type="password"` 只是遮住显示内容，不代表加密或认证。

账号密码属于当前登录表单。后台头部需要的是昵称等用户信息，不需要共享密码，所以不要把密码放入全局 store 或浏览器存储。

### 2.2 局部状态、共享状态和持久化

- `form`、错误文案、按钮 loading：本页面负责的局部状态。
- 当前用户、token：多个页面和请求层使用的共享状态，适合放入 Pinia。
- 浏览器存储：用来在刷新后重新读取数据，不会自动与 Pinia 同步。

`sessionStorage` 的值是字符串，刷新通常仍在，同一标签页的页面会话结束后清除。`localStorage` 通常可在关闭浏览器后保留。二者都不是响应式对象；读取一次后，其他地方改存储不会自动更新已有的 Vue 状态。

保存对象要用 `JSON.stringify()`，恢复对象要用 `JSON.parse()`。后者遇到不合法 JSON 会抛错，而且解析成功也不保证字段类型正确。

### 2.3 异步结果与 finally

```ts
try {
  const result = await login(input)
  // 只有 login 成功兑现 Promise，才会执行这里。
} catch (error) {
  // login 拒绝 Promise，或 try 内的操作抛错，进入这里。
} finally {
  // 成功和失败都要结束等待状态。
}
```

`async` 函数返回 Promise。`await` 暂停当前函数后续步骤，不会把整个页面冻结。`throw new Error('账号或密码错误')` 出现在 async 函数中，会使该函数返回的 Promise 失败。

## 3. 核心概念

### 3.1 跳转不等于登录成功

`router.push('/admin/home')` 只改变页面地址并导航，不会验证账号密码，也不会生成 token。

真实登录要由服务器检查凭证。成功时服务器返回身份信息和凭证；前端保存结果，再导航。前端校验、前端 store、路由守卫都不能替代服务器对受保护接口的鉴权。

### 3.2 三种数据不要混淆

| 数据 | 例子 | 作用 |
| --- | --- | --- |
| 账号密码 | admin / 输入的密码 | 提交给服务器验证身份 |
| token | 服务器签发的一串凭证 | 后续请求携带，让服务器识别会话 |
| 用户信息 | id、username、nickname | 显示当前用户和描述用户身份 |

token 不一定是 JWT，也不能通过“有一串非空字符串”就证明会话仍有效。服务器可能判定它过期或已撤销。前端的 `isLoggedIn = Boolean(token)` 只是本地状态判断。

本课延续现有请求层的 `Authorization: Bearer <token>` 约定，真实后端必须支持同一约定。生产项目如何使用 Cookie、token 及过期策略，需要前后端共同设计；本课的浏览器存储例子是教学实现。

### 3.3 Element Plus 表单校验需要四处连起来

```vue
<el-form ref="formRef" :model="form" :rules="rules">
  <el-form-item label="账号" prop="username">
    <el-input v-model="form.username" />
  </el-form-item>
</el-form>
```

- `model`：整份表单数据。
- `rules`：每个字段的校验规则。
- `prop="username"`：告诉这一项检查 model 中的 username，并找到同名规则。
- `ref="formRef"`：让脚本取得表单组件实例，调用它的 `validate()`。

```ts
const formRef = ref<FormInstance>()
const rules: FormRules = {
  username: [{ required: true, message: '请输入账号', trigger: 'blur' }],
}
```

`FormInstance` 是组件实例类型，`FormRules` 描述规则结构，二者用 `import type` 导入。挂载前实例可能不存在，因此调用前需要检查。`blur` 表示输入框失去焦点时检查；提交时主动 `validate()` 会整体检查。

不传回调时，校验不通过可能拒绝 Promise。教材用 `await formRef.value.validate().catch(() => false)` 将它变成布尔结果；错误信息由表单项显示，不当成服务器登录失败。

### 3.4 校验输入和认证身份分工不同

前端可检查“账号非空”“密码至少六位”，减少明显无效的提交。满足这些规则不代表密码正确；服务器还要查账号、核对密码、检查账号状态。

教材中的六位规则只用于示范，不是 BuildAdmin 密码规则的原样复刻。正式项目应与后端约定保持一致。不要擅自对密码 `trim()`，空格可能就是密码的一部分。

### 3.5 状态更新顺序

```text
校验通过 → 开始等待 → 登录接口成功
                        ↓
                保存 token 和用户信息
                        ↓
                    跳转后台
```

接口失败就进入错误分支，不执行保存和成功跳转。保存应在跳转之前，否则后台组件或紧接着发出的请求可能读到空身份。

`finally` 负责关闭 loading。按钮的 loading 配合函数开头的 `if (submitting.value) return`，可以阻止重复触发。应在等待校验前就设置锁，避免多次点击同时通过异步校验。

### 3.6 让 store 与请求层读取同一份身份

当前练习项目中，`src/stores/user.ts` 保存内存 token，而 `src/utils/http.ts` 读取 `sessionStorage.getItem('token')`。仅调用 `setUser()` 不会自动写入这个存储键，因此可能出现“头部显示已登录，请求却没带 token”。

可以让 store 同时维护这个键，也可以让请求拦截器直接读 store。教材完整示例选择后者：store 管理身份和持久化，请求层每次从 store 取当前 token。两种方案都能实现，但读取与写入必须配套。

`useUserStore()` 放在请求回调内调用，应用发送请求前应已经执行 `app.use(pinia)`。当前项目入口满足安装 Pinia 再使用应用的顺序。

### 3.7 持久化策略与“保持登录”

Pinia 核心只管理内存状态。项目可以手写 sessionStorage/localStorage 保存与恢复，也可以注册 `pinia-plugin-persistedstate` 统一完成。课堂最终采用插件方案，因为这更接近 BuildAdmin，学生不必在本节维护两套存储分支。

插件默认使用 localStorage。当前最小登录页不显示“保持登录”，因为没有提供不同的会话期限选择，避免界面承诺无效功能。真实系统还需要服务器控制会话有效期；本地仍有 token 不代表服务器一定接受它。密码不能进入 store 或持久化数据。

## 4. BuildAdmin 源码拆解

以下依据本机 `F:/project/MyProject/buildadmin` 中的源码阅读，不把教学约定当作原项目行为。

### 4.1 页面：web/src/views/backend/login.vue

页面用 `form` 保存 `username`、`password`、`keep` 和验证码相关字段。`rules` 借助 `buildValidatorData()` 构建账号与密码规则。

挂载后调用 `login('get')`，读取是否展示验证码等登录初始化信息。这不是提交账号密码。提交入口 `onSubmitPre()` 先调用表单 `validate()`，校验通过后根据配置决定是否经过验证码，再调用 `onSubmit()`。

核心链路如下，省略装饰性界面和验证码细节：

```ts
state.submitLoading = true
login('post', form)
  .then((res) => {
    adminInfo.dataFill(res.data.userInfo, false)
    router.push({ path: adminBaseRoutePath })
  })
  .finally(() => {
    state.submitLoading = false
  })
```

先得到登录响应，再填 store，随后导航；最后恢复按钮。这就是要学习的骨架。`keep` 在这里随表单发给后端，不能仅凭这个文件断言它等同于切换 localStorage。

### 4.2 API：web/src/api/backend/index.ts

`login(method, params)` 调用 `createAxios()`，请求地址由 `/admin/Index/` 加 `login` 组成，参数放入 `data`，方法由调用方传入。页面调用 POST 提交登录信息。

这层负责登录接口的地址和传输方式，不负责昵称如何显示，也不直接跳页面。

### 4.3 状态：web/src/stores/adminInfo.ts

store 保存账号、昵称、token、refresh_token 等。`dataFill(state, exclude = true)` 默认排除两种 token；传 `false` 表示不排除，因此登录页的第二个实参非常重要。

`this.$patch(state)` 批量更新字段，可以理解成把服务器给的身份资料填写到共享身份卡上。`getToken()` 读取对应凭证，`removeToken()` 清空两类凭证，不会同时清空全部昵称等字段。

文件末尾有 `persist: { key: ADMIN_INFO }`，配合 `web/src/stores/index.ts` 中注册的 `pinia-plugin-persistedstate` 实现持久化。普通 Pinia 本身不会因为写一个 persist 对象就自动持久化；练习项目没有安装这个插件，所以教材展示手动存取的过程。

### 4.4 请求：web/src/utils/axios.ts

请求拦截器通过 `adminInfo.getToken()` 读取管理端凭证，并根据客户端选项设置请求头。这样页面保存身份后，后续接口能获取凭证。原项目还处理用户端凭证、刷新等情况，本节只追踪管理端主线。

BuildAdmin 的默认精简响应返回整个业务响应体，因此页面写 `res.data.userInfo`。你的第 15 节 `request<T>()` 已经通过 `res.data.data` 解包，返回的直接是 T；接入时不要再照抄多余的 `.data`。

## 5. 完整示例与运行过程

这是可独立阅读、在当前 Vue 项目结构中运行的参考实现，不是要求一次复制的作业。课堂会逐步指定修改文件。上节你选择暂不搭模拟 API，因此下面的本地登录函数仅用于展示完整成功/失败链路，不会由 Coach 自动加入业务源码；真实后端接入位置也在后面明确给出。

### 5.1 状态端：src/stores/user.ts

此版本保留现有 store 对外字段和方法，增加会话存取。代码只接受基本字段类型正确且 token 非空的缓存；这仍不是服务器认证。

```ts
import { defineStore } from 'pinia'
import { computed, ref } from 'vue'

export interface UserProfile {
  id: number
  username: string
  nickname: string
  token: string
}

const sessionKey = 'ba-learn-user'

function readSession(): UserProfile | null {
  try {
    const raw = sessionStorage.getItem(sessionKey)
    const value: unknown = raw ? JSON.parse(raw) : null
    if (
      typeof value === 'object' && value !== null &&
      'id' in value && typeof value.id === 'number' &&
      'username' in value && typeof value.username === 'string' &&
      'nickname' in value && typeof value.nickname === 'string' &&
      'token' in value && typeof value.token === 'string' && value.token !== ''
    ) {
      return {
        id: value.id, username: value.username,
        nickname: value.nickname, token: value.token,
      }
    }
  } catch {
    // 缓存损坏或存储不可读时，以未登录状态启动。
  }
  return null
}

export const useUserStore = defineStore('user', () => {
  const cached = readSession()
  const id = ref(cached?.id ?? 0)
  const username = ref(cached?.username ?? '')
  const nickname = ref(cached?.nickname ?? '')
  const token = ref(cached?.token ?? '')
  const displayName = computed(() => nickname.value || username.value || '未登录')
  const isLoggedIn = computed(() => Boolean(token.value))

  function persist() {
    sessionStorage.setItem(sessionKey, JSON.stringify({
      id: id.value, username: username.value,
      nickname: nickname.value, token: token.value,
    }))
  }

  function setUser(profile: UserProfile) {
    // 先保存；若写入失败，由调用方处理，不留下半完成的内存登录态。
    sessionStorage.setItem(sessionKey, JSON.stringify(profile))
    id.value = profile.id
    username.value = profile.username
    nickname.value = profile.nickname
    token.value = profile.token
  }

  function updateNickname(value: string) {
    nickname.value = value.trim()
    if (token.value) persist()
  }

  function clearUser() {
    sessionStorage.removeItem(sessionKey)
    id.value = 0
    username.value = ''
    nickname.value = ''
    token.value = ''
  }

  return {
    id, username, nickname, token, displayName, isLoggedIn,
    setUser, updateNickname, clearUser,
  }
})
```

`cached?.id` 表示有缓存时读取 id，否则得到 undefined；`?? 0` 在结果为 null 或 undefined 时提供默认值。恢复发生在 store 第一次创建时。后续调用同一 store 获取共享实例，不会每次重读缓存。

示例假定浏览器允许写入 sessionStorage；若禁止存储，登录页会接到写入错误。本节不实现跨标签页同步。昵称在客户端修改仍是本地练习行为，不会因此更新服务器用户资料。

### 5.2 返回结果端：src/api/auth.ts（仅教学演示版本）

```ts
import type { UserProfile } from '@/stores/user'

export interface LoginInput {
  username: string
  password: string
}

export async function login(input: LoginInput): Promise<UserProfile> {
  await new Promise<void>((resolve) => window.setTimeout(resolve, 500))
  if (input.username !== 'admin' || input.password !== '123456') {
    throw new Error('账号或密码错误')
  }
  return {
    id: 1,
    username: 'admin',
    nickname: '学习管理员',
    token: 'demo-token-only',
  }
}
```

输入端传入账号密码，结果端等候半秒，然后成功返回 UserProfile 或抛错。这里的固定账号和 token 都是演示数据，不发送 HTTP，不经过 Axios 拦截器，也不能认证真实服务器。不要把这段前端判断当作真实登录实现。

### 5.3 输入端：src/views/login/LoginView.vue

下面是完整的最小组件。现有品牌区和 CSS 可以保留，只替换对应表单逻辑。不要在同一文件中重复加入第二个 script setup。

```vue
<script setup lang="ts">
import { reactive, ref } from 'vue'
import { useRouter } from 'vue-router'
import type { FormInstance, FormRules } from 'element-plus'
import { login } from '@/api/auth'
import { useUserStore } from '@/stores/user'

const router = useRouter()
const userStore = useUserStore()
const formRef = ref<FormInstance>()
const form = reactive({ username: '', password: '' })
const submitting = ref(false)
const message = ref('')
const rules: FormRules = {
  username: [
    { required: true, whitespace: true, message: '请输入账号', trigger: 'blur' },
  ],
  password: [
    { required: true, message: '请输入密码', trigger: 'blur' },
    { min: 6, message: '密码至少六位', trigger: 'blur' },
  ],
}

async function handleSubmit() {
  if (submitting.value || !formRef.value) return
  submitting.value = true
  message.value = ''
  try {
    const valid = await formRef.value.validate().catch(() => false)
    if (!valid) return
    const result = await login({
      username: form.username.trim(),
      password: form.password,
    })
    userStore.setUser(result)
    form.password = ''
    await router.replace('/admin/home')
  } catch (error) {
    message.value = error instanceof Error ? error.message : '登录未完成，请稍后重试'
  } finally {
    submitting.value = false
  }
}
</script>

<template>
  <el-form
    ref="formRef"
    :model="form"
    :rules="rules"
    @submit.prevent="handleSubmit"
  >
    <el-form-item label="账号" prop="username">
      <el-input v-model="form.username" autocomplete="username" />
    </el-form-item>
    <el-form-item label="密码" prop="password">
      <el-input
        v-model="form.password"
        type="password"
        show-password
        autocomplete="current-password"
      />
    </el-form-item>
    <el-button type="primary" native-type="submit" :loading="submitting">
      登录
    </el-button>
    <p v-if="message" role="alert">{{ message }}</p>
  </el-form>
</template>
```

`native-type="submit"` 让按钮提交表单，`@submit.prevent` 阻止原生页面刷新并调用处理函数，也支持 Enter 提交。没有同时绑定 click，避免一次操作调用两次。

`replace` 用后台地址替换当前登录历史项，避免这次登录产生一个可直接后退到的登录记录；它不是权限控制。`error instanceof Error` 缩小未知错误类型后才能可靠读取 message。

### 5.4 传输端：src/utils/http.ts

延续上一节“拦截器返回完整 response、request<T> 解包”的最终方案，只把 token 来源改成 store。

```ts
import axios from 'axios'
import type { AxiosRequestConfig } from 'axios'
import type { ApiResponse } from '@/api/types'
import { useUserStore } from '@/stores/user'

export const http = axios.create({
  baseURL: import.meta.env.VITE_API_BASE_URL,
  timeout: 10000,
})

http.interceptors.request.use((config) => {
  const token = useUserStore().token
  if (token) config.headers.Authorization = `Bearer ${token}`
  return config
})

http.interceptors.response.use(
  (res) => {
    const body: ApiResponse<unknown> = res.data
    if (body.code !== 1) return Promise.reject(new Error(body.message))
    return res
  },
  (error) => Promise.reject(error),
)

export async function request<T>(config: AxiosRequestConfig): Promise<T> {
  const res = await http.request<ApiResponse<T>>(config)
  return res.data.data
}
```

依赖的 `src/api/types.ts` 中已有以下结构，保留原文件其他类型即可：

```ts
export interface ApiResponse<T> {
  code: number
  message: string
  data: T
}
```

注意 store 不导入 auth 或 http，避免“http 依赖 store、store 又依赖 http”的循环。本例由页面协调登录 API 和 store。

### 5.5 接真实后端时替换哪里

将 `src/api/auth.ts` 的演示函数替换为下面的真实传输版本，其他页面调用方式可以保持不变：

```ts
import { request } from '@/utils/http'
import type { UserProfile } from '@/stores/user'

export interface LoginInput {
  username: string
  password: string
}

export function login(input: LoginInput): Promise<UserProfile> {
  return request<UserProfile>({
    url: '/login',
    method: 'POST',
    data: input,
  })
}
```

这是建议给后续 Spring Boot 后端对接的示例契约，不代表当前服务器已有此接口：

```text
POST <VITE_API_BASE_URL>/login
Content-Type: application/json
请求体：{"username":"admin","password":"输入的密码"}

成功响应体：
{"code":1,"message":"ok","data":{"id":1,"username":"admin","nickname":"管理员","token":"服务器签发的凭证"}}

业务失败响应体（示例使用 HTTP 200）：
{"code":0,"message":"账号或密码错误","data":null}
```

服务器负责校验凭证并签发 token。前端响应拦截器让 `code !== 1` 进入失败分支；成功时 request 已解包，因此 `result` 就是用户资料。若真实服务器选择 HTTP 401，Axios 会进入传输失败分支，也不会执行保存与跳转；详细错误文案映射留待第 18 节。

真实版本需要后端实际运行、地址配置正确、跨域或代理配置可用才能验证。目前尚未接通，不能把类型检查通过当作登录接口验证通过。

1. 留空提交：表单显示必填提示，未调用 login。
2. 密码少于六位：显示长度提示。
3. 输入 admin / 000000：校验通过，按钮等待半秒，随后提示账号或密码错误，留在登录页。
4. 输入 admin / 123456：保存用户资料，跳转 `/admin/home`。现有 AdminHeader 从 store 读取 displayName，应显示“学习管理员”。
5. 刷新后台页面：store 从 sessionStorage 恢复，昵称仍可显示。这只能说明本地恢复成功，不能证明服务端会话有效。
6. 后续真实 API 请求会从 store 取 token。演示 token 不具备真实授权能力，不能据此要求真实用户接口返回成功。

调试时可在应用组件中调用 `userStore.clearUser()` 验证清理，它会删除缓存并清空内存。本节示例没有退出按钮、服务器注销、标签缓存清理或路由拦截；完整登录访问控制在后续课程补齐。

## 6. 常见错误

1. **按钮直接跳转。** 没有等待登录结果，错误账号也能进入页面。
2. **只加 rules、不加 prop。** 表单项无法对应字段规则，界面看似配置了校验却不能按预期工作。
3. **校验通过就认定身份正确。** 格式检查与服务器认证是两个环节。
4. **把 token 放在表单中，其他页面读不到。** 成功结果需要进入共享状态。
5. **store 和请求层读写不同位置。** 用户名显示正常不等于请求已经携带凭证。
6. **刷新后丢失用户。** Pinia 内存会重建，持久化需要保存和恢复两个动作。
7. **失败后按钮一直转圈。** loading 应在 finally 中恢复，包括校验失败后的提前 return。
8. **凭据被保存在缓存中。** 密码只用于提交，不放进 UserProfile 或持久化对象。
9. **照抄 BuildAdmin 的 res.data.userInfo。** 先检查自己的请求封装到底返回哪一层数据。
10. **把前端 token 当成安全边界。** 本地数据可修改，受保护接口必须由服务端鉴权。

## 7. 自测题

1. 为什么执行 router.push 不能说明登录成功？
2. model、rules、prop、formRef 分别有什么作用？
3. 一个六位密码通过前端校验后，服务器为什么仍然可能拒绝登录？
4. 登录成功后，为什么先 setUser 再跳转？
5. 头部显示昵称，但请求没有 token，应该检查哪条数据链？
6. 只保存到 sessionStorage、不写恢复逻辑，刷新后 store 会自动恢复吗？
7. BuildAdmin 登录页为什么给 dataFill 传 false？
8. 演示登录成功能否证明 Axios 请求和真实后端已经接通？

## 8. 参考答案

1. 路由只负责导航，没有核对凭证或签发会话。身份认证要由服务器完成，前端拿到成功结果再进入成功流程。
2. model 提供字段值，rules 给出检查规则，prop 将表单项对应到字段，formRef 让脚本调用整个表单的校验方法。四者职责不同。
3. 六位只满足长度要求，账号可能不存在、密码可能不匹配、账号可能禁用。前端不了解服务器保存的真实认证信息。
4. 目标页面和请求层可能立即读取身份，先保存才能让它们读到新状态。
5. 检查登录结果写入哪里、请求拦截器从哪里读取，以及键名和请求头是否与后端契约一致。昵称与 token 可能来源不同。
6. 不会。浏览器存储与 Vue 状态是独立机制，要在初始化时读取并填回状态。安装且正确配置的持久化插件可以代做这件事。
7. dataFill 默认排除 token 和 refresh_token；传 false 才会把登录响应中的两种凭证也填入 store。
8. 不能。演示函数直接返回 Promise，没有经过 HTTP。真实链路仍需要服务端、客户端配置及成功失败请求验证。
