# 第 14 节学习资料：标签页导航与页面缓存

## 1. 学习目标

把访问过的页面显示为标签，支持新增、切换和关闭；首页固定保留；理解路由、标签列表和页面缓存是三种不同的数据。能说明输入为何在切换后保留，以及关闭和刷新为什么需要单独设计。

## 2. 前置知识

### 2.1 当前页面与访问记录

`useRoute()` 提供当前路由，`useRouter()` 提供导航方法。`router.push('/admin/home')` 请求进入首页。`route.path` 是路径，`route.fullPath` 还包含查询参数和 hash，`route.name` 是路由记录的名称。

例如访问 `/admin/users/8?from=menu`：path 是 `/admin/users/8`，fullPath 是整个地址，name 可以是 `user-detail`。用户 8 和用户 9 的 name 可以相同，fullPath 不同。

一个 route 只描述现在在哪里，不能独自保存“之前还打开了哪些页面”。后者需要一个数组。Pinia 可以让标签栏和内容区共同读取这个数组。

### 2.2 本节会用到的语法

- `ref([])` 创建响应式数组；脚本中通过 `.value` 读写，模板中自动解包。
- `computed(() => ...)` 从已有状态计算新结果，例如从标签中得到需要缓存的组件名称。
- `watch(() => route.fullPath, callback, { immediate: true })` 监听地址变化，并在建立监听时先执行一次。首次直接打开用户详情也能登记标签。
- `find()` 找出第一个符合条件的元素，没找到返回 undefined；`findIndex()` 返回位置，没找到返回 -1；`filter()` 返回保留下来的新数组。
- `array.splice(index, 1)` 从指定位置删除一个元素。
- `v-for` 根据数组生成标签；`:key` 帮助 Vue 识别节点身份；`@click` 响应点击。
- `async` 函数中的 `await router.push(...)` 等待这次导航的结果，避免页面还没切换就先删除当前标签。

这些语法会在下面的完整示例中出现，不需要先背熟。

## 3. 核心概念

### 3.1 三份信息各管什么

| 信息 | 例子 | 职责 |
| --- | --- | --- |
| 当前路由 | `/admin/users/8` | 决定显示哪页、哪个标签高亮 |
| 标签列表 | 首页、用户详情 | 记住打开过的入口 |
| 页面实例 | 用户详情组件及其中的输入 | 保留页面运行中的局部状态 |

数组中有“用户详情”这一项，不代表输入框的内容也保存了。标签栏本质上是一组能导航的入口。

### 3.2 meta 是附加说明，不是自动功能

路由配置可以包含 `meta: { title: '用户详情', tab: true, cacheName: 'UserDetailView' }`。这些是本示例自定义的字段。必须由业务代码读取它们，才能产生标签和缓存行为。只写 `keepAlive: true` 不会自动缓存。

输入端是路由配置，处理端是监听 route 的代码，输出端是标签列表和缓存名称数组。Vue Router 会把匹配到的路由元信息提供给当前 route。[官方说明：Route Meta Fields](https://router.vuejs.org/guide/advanced/meta.html)

### 3.3 KeepAlive 缓存的是组件实例

普通页面组件切走后可能卸载，重新进入时 `ref('')` 再次从空字符串开始。KeepAlive 能保留被切走的实例。它的 `include` 匹配组件名称，例如 `UserDetailView`，不是路由名 `user-detail`。`key` 则用于区分具体实例。[官方说明：KeepAlive](https://vuejs.org/guide/built-ins/keep-alive.html)

通过 RouterView 的作用域插槽取出页面组件，再把这个组件放入 KeepAlive。`v-slot="{ Component }"` 表示接收 RouterView 提供的 Component；`<component :is="Component" />` 表示渲染它。[官方说明：RouterView slot](https://router.vuejs.org/guide/advanced/router-view-slot.html)

### 3.4 关闭策略必须明确

本课基础版本使用以下规则：固定首页不能关闭；关闭非当前标签不跳转；关闭当前标签优先去右邻居，没有右邻居则去左邻居，最终可回到首页。删除标签不等于删除路由，之后仍可以从菜单再次打开。

KeepAlive 的内存会随整页刷新或其所在组件卸载而消失。持久化标签数组也不能自动持久化组件实例。输入需要跨刷新保留时，要另外保存表单数据。

## 4. BuildAdmin 源码拆解

### 4.1 标签状态：web/src/stores/navTabs.ts

`state.tabsView` 是打开的标签列表，`activeRoute`、`activeIndex` 描述激活项。`_addTab(route)` 先检查 `meta.addtab`，不允许加标签就返回；再寻找原始菜单信息，并按菜单 id 或 fullPath 判断是否已存在。已存在时更新路径、params 和 query，否则追加。

因此 BuildAdmin 并非无条件按 fullPath 为每个参数创建新标签。本课示例选择 fullPath 去重，是便于观察的简化规则，不能当成源码原样实现。

`_closeTab(route)` 从数组删除匹配项。公开的 `closeTabByPath()` 通过 `layoutNavTabsRef` 调用标签组件的关闭方法，因为关闭还涉及跳转和缓存通知，不只是数组操作。

### 4.2 标签交互：web/src/layouts/backend/components/navBar/tabs.vue

`updateTab(newRoute)` 调用 `_addTab()` 和 `_setActiveRoute()`。首次挂载时登记当前路由，`onBeforeRouteUpdate()` 中更新标签。关闭流程会发送 `onTabViewClose` 事件，通知内容区处理缓存。真实项目还包含横向滚动、右键菜单和刷新标签，本课不要求复制这些功能。

### 4.3 页面缓存：web/src/layouts/backend/router-view/main.vue

模板的关键结构是：

```vue
<router-view v-slot="{ Component }">
  <transition :name="config.layout.mainAnimation" mode="out-in">
    <keep-alive :include="state.keepAliveComponentNameList">
      <component :is="Component" :key="state.componentKey" />
    </keep-alive>
  </transition>
</router-view>
```

`componentKey` 随 fullPath 变化；`addActiveRouteKeepAlive()` 从菜单路由的 `meta.keepalive` 取组件名称，加入缓存名单；关闭事件把对应名称从名单移除。刷新标签事件先移除名称，再通过 `nextTick()` 等待一次 Vue 更新后重新设置 key 和名称。

通俗地说：标签栏负责“入口还要不要”，内容区负责“这个页面实例还留不留”。事件把两边串起来。本课改用共享 store 的派生名单，先学核心链路，不增加事件总线。

### 5.4 tabs.ts：处理端，保存访问记录

```ts
import { computed, ref } from 'vue'
import { defineStore } from 'pinia'
import type { RouteLocationNormalizedLoaded } from 'vue-router'

export interface Tab {
  fullPath: string
  title: string
  fixed: boolean
  cacheName: string
}

export const useTabs = defineStore('lesson14-tabs', () => {
  const tabs = ref<Tab[]>([
    { fullPath: '/admin/home', title: '首页', fixed: true, cacheName: 'HomeView' },
  ])

  const cacheNames = computed(() =>
    tabs.value.map(tab => tab.cacheName).filter(name => name !== ''),
  )

  function add(route: RouteLocationNormalizedLoaded) {
    if (route.meta.tab !== true) return
    if (tabs.value.find(tab => tab.fullPath === route.fullPath)) return
    tabs.value.push({
      fullPath: route.fullPath,
      title: typeof route.meta.title === 'string' ? route.meta.title : route.path,
      fixed: route.path === '/admin/home',
      cacheName: typeof route.meta.cacheName === 'string' ? route.meta.cacheName : '',
    })
  }

  function remove(fullPath: string) {
    const index = tabs.value.findIndex(tab => tab.fullPath === fullPath)
    const tab = tabs.value[index]
    if (!tab || tab.fixed) return
    tabs.value.splice(index, 1)
  }

  return { tabs, cacheNames, add, remove }
})
```

固定首页一开始就存在；未访问的组件不会仅因名字在 include 中就自动创建。`typeof ... === 'string'` 检查元信息的实际类型，避免把未知值直接当字符串使用。

### 5.5 App.vue：输出端，标签栏与页面出口

```vue
<script setup lang="ts">
import { watch } from 'vue'
import { RouterLink, RouterView, useRoute, useRouter } from 'vue-router'
import { useTabs, type Tab } from './tabs'

const route = useRoute()
const router = useRouter()
const store = useTabs()

watch(() => route.fullPath, () => store.add(route), { immediate: true })

async function closeTab(tab: Tab) {
  if (tab.fixed) return
  const index = store.tabs.findIndex(item => item.fullPath === tab.fullPath)
  if (index === -1) return
  if (route.fullPath === tab.fullPath) {
    const next = store.tabs[index + 1] ?? store.tabs[index - 1]
    const failure = await router.push(next?.fullPath ?? '/admin/home')
    if (failure) return
  }
  store.remove(tab.fullPath)
}
</script>

<template>
  <aside>
    <RouterLink to="/admin/home">首页菜单</RouterLink>
    <RouterLink to="/admin/users/8">用户详情菜单</RouterLink>
  </aside>
  <nav aria-label="已打开页面">
    <span v-for="tab in store.tabs" :key="tab.fullPath" class="tab">
      <button
        :class="{ active: route.fullPath === tab.fullPath }"
        @click="router.push(tab.fullPath)"
      >{{ tab.title }}</button>
      <button v-if="!tab.fixed" aria-label="关闭标签" @click="closeTab(tab)">×</button>
    </span>
  </nav>
  <main>
    <RouterView v-slot="{ Component, route: viewRoute }">
      <KeepAlive :include="store.cacheNames">
        <component :is="Component" :key="viewRoute.fullPath" />
      </KeepAlive>
    </RouterView>
  </main>
</template>

<style scoped>
aside, nav { display: flex; gap: 12px; padding: 12px; }
.tab { display: inline-flex; }
.active { color: #1769d2; font-weight: bold; }
main { padding: 16px; }
</style>
```

`next?.fullPath` 是可选链：next 不存在时得到 undefined；`??` 再提供首页兜底。关闭按钮与跳转按钮互为兄弟，所以点击关闭不会同时冒泡触发跳转按钮；若改成外层整体可点击，就要考虑 `@click.stop`。

### 5.7 从启动到关闭的完整运行过程

1. 启动应用，注册 Pinia 和路由，进入首页。标签数组初始已有首页，监听器不会重复添加。
2. 点击用户详情菜单，路由变成 `/admin/users/8`，监听器新增标签，include 增加 `UserDetailView`，页面首次挂载并激活。
3. 输入“待联系”，切回首页。详情实例进入缓存，打印停用信息。
4. 点击详情标签返回。恢复的是已有实例，备注仍为“待联系”，打印激活信息，不再次挂载。
5. 点击详情标签的关闭按钮。先切回首页，再删除标签，派生缓存名单移除 `UserDetailView`，旧实例随后卸载。
6. 从菜单重新进入详情。路由仍存在，标签重新加入，创建新的实例，备注为空。
7. 整页刷新后内存重建。本例的旧标签历史和局部输入都不会保留；当前页面会由监听器重新登记。

这些是示例的预期行为；本次开课仅提供教材，尚未创建或运行 demo，也未修改学生的业务代码。

### 5.9 课堂补充：使用 Element Plus Tabs 代替普通按钮

当前学生选择 el-tabs 方案，以下完整讲解同样适用于复习。保留 5.5 的原生按钮独立示例；练习中无需两种方案同时实现。

看到了，你改用了 **Element Plus 的 `el-tabs`，可以沿着这个方案继续**，不用换回普通按钮。

你已经写好了遍历和标题显示。现在卡住的关键是：**点击回调收到的 `tab`，不是 store 数组里的那个标签对象。**

模板里的：

```vue
v-for="tab in navTabs.tabs"
```

这里的 `tab` 是你定义的 `NavTab`，有 `title`、`fullPath`、`fixed`。

而：

```ts
const handleClick = (tab: TabsPaneContext) => {}
```

这里的 `tab` 是 Element Plus 提供的标签面板信息。两个变量虽然都叫 tab，但来源不同；组件接收到的 `name` 可以通过 `tab.props.name` 读取。

所以要把地址传进去，再在点击时取出来。

**第一处：把 pane 的 name 改为地址。**

```vue
<el-tab-pane
  v-for="tab in navTabs.tabs"
  :key="tab.fullPath"
  :label="tab.title"
  :name="tab.fullPath"
/>
```

三个属性分别负责：

- `key`：让 Vue 识别循环节点。
- `label`：标签上显示的文字。
- `name`：让 Element Plus 识别和选中标签。

你原来的 `:name="tab.title"` 传进去的是“用户详情”，不能直接拿它当页面地址。原来面板里的 `User` 是示例内容，可以去掉；真正的页面由下方的 `RouterView` 显示。

**第二处：点击时读取 name，交给 router。**

```ts
const handleClick = (tab: TabsPaneContext) => {
  const path = tab.props.name
  if (typeof path !== 'string') return

  router.push(path)
}
```

类型检查是因为组件库允许 name 使用字符串或数字，而这里需要字符串地址。你现在直接导入项目里的 router 实例也可以，不必改成 useRouter。

这条链路实际是：

```text
数据中的 tab.fullPath = '/admin/users/8'
→ 传给 el-tab-pane 的 name
→ 点击时 tab.props.name 得到 '/admin/users/8'
→ router.push('/admin/users/8')
```

**第三处：让当前路由决定选中项。**

给外层 `el-tabs` 加上：

```vue
:model-value="route.fullPath"
```

它会根据这个值匹配 pane 的 `name`，显示对应选中样式，不用再手动添加 active 类。这里用单向绑定，不要写 `v-model="route.fullPath"`：改变路由应通过 router 导航，而不是直接修改 route。[Element Plus Tabs 文档](https://element-plus.org/en-US/component/tabs.html)

先在 [AdminTabs.vue](F:/project/MyProject/ba-learn/src/layouts/components/AdminTabs.vue) 补好这三处，保留现有 watch。**这一步的核心就是：把 fullPath 作为标签标识，点击时取它导航，路由变化后用它同步选中项。**

## 6. 常见错误

1. 只在菜单点击时添加标签：程序跳转、首次直接访问和历史导航可能漏记，应监听实际路由变化。
2. 标签标题直接当唯一标识：同标题可能对应不同页面。先定义规则，再选择 fullPath 或路由 name。
3. 用 route.name 区分用户 8 和用户 9：两者可能同名。如果产品要分别打开，应设计 fullPath 等更细的标识。
4. 认为 include 匹配路由名：实际匹配组件名。声明和名单不一致就不能按预期缓存。
5. 把 KeepAlive 包在整个 RouterView 外面：应通过插槽把目标页面组件放入缓存容器。
6. 每次切换给 KeepAlive 本身设置变化的 key：整个缓存容器重建会丢失缓存。需要区分实例时设置页面 component 的 key。
7. 关闭当前标签只删数组：页面还在，标签却消失。应先成功导航到保留标签，再移除原标签。
8. 以为隐藏关闭按钮就够了：删除方法也要保护固定首页，避免其他入口误删。
9. 以为移除一个组件名称能精准关闭某个用户实例：include 按组件类型名称筛选。如果多个标签共用 UserDetailView，删除这个名字会影响全部同名缓存；保留名字又不能精准清除其中一个实例。本课只验收首页与一个详情标签。多实例精准释放需要进一步设计包装组件或单独管理草稿，不访问 Vue 私有缓存字段。
10. 以为缓存后 onMounted 每次切回来都执行：它只在该实例挂载时执行；恢复时用 onActivated。onActivated 首次挂载也执行，onDeactivated 卸载时也会触发，副作用需要正确清理。

## 7. 自测题

1. 标签数组里存了标题和 URL，为什么备注仍可能丢失？
2. 浏览器后退时，没有点击标签，标签高亮怎样保持正确？
3. 关闭非当前标签需要跳转吗？关闭当前标签呢？
4. route.name 是 user-detail，组件名是 UserDetailView，include 应填哪个？
5. `/admin/users/8` 和 `/admin/users/9` 使用同一组件时，标签身份和实例身份分别要考虑什么？
6. 关闭标签再重开，与切换到别页再回来，有何不同？
7. 刷新后标签列表恢复了，是否代表之前的组件实例也恢复了？

## 8. 参考答案

1. 标签数组只是导航记录，备注属于页面实例的局部状态；实例被销毁后新实例会重新初始化。
2. 以当前 route 计算高亮，并在路由变化时登记标签。路由是事实来源，不另存“最后点击项”代替它。
3. 非当前标签只删除，不打断当前页面；当前标签关闭前需要找到保留的邻居或首页，并切过去。
4. UserDetailView。include 检查组件名称，不检查路由名称。
5. 若要分别打开，不能仅用共同的 route.name；fullPath 可以区分访问地址。实例还需要合适的 key，同时必须承认 include 按组件名清理的粒度限制。
6. 普通切换希望保留实例，关闭通常希望释放对应缓存，重新打开从初始状态开始；标签删除与缓存释放需要两端配合。
7. 不代表。数组可序列化保存，组件实例是当前运行时对象，刷新会重建应用。需要恢复草稿时另行持久化业务数据。
